## 真实验收暴露并修复的问题

1. 工具 JSON Schema 中 UUID 格式、未标注类型的常量及可空类型数组超出 DSH 当前支持的子集。适配器转换传输描述，Rust 仍保留原始业务校验；不删除权限、版本或结构保护。
2. 模型网关在正常 Token 用量之后另发只有金额的用量帧，覆盖 SDK 的 Token 用量并使会话结束失败。原始金额帧完整保存，SDK 继续使用真正的 Token 回执，不伪造数量或费用。
3. 后续工具参数片段带空名称、空标识，覆盖原工具身份。转交 SDK 时省略这些空字段，保留已有名称、标识及完整参数。
4. worker 的错误原因曾在跨进程传递时丢失。原始嵌套原因现在经过密钥清理后进入私有执行诊断；公开提示保持简短。
5. HTTP 402 是明确的额度拒绝，不应当作“是否执行未知”。现已按未执行记录并返回适当的公开失败提示，不盲目重复发送。
6. 每个微小流式片段曾分别提交数据库。在隔离测试机同时运行回归时，单次事务提交中位数约 31 毫秒。现将相邻文字片段按短时间片合并落库，并在工具调用、检查点、结束前刷新；保留全部 Unicode 文字、顺序和原事件身份。失败也保存已经接收的部分文字及原始错误。40 毫秒刷新间隔和 16 KiB 批次是传输合并条件，均不是输出总量上限。专门回归验证完整文字、空闲刷新、错误保留及写入次数下降。前后专业样例内容、模型行为与并行负载不同，不能将全部耗时差归因于这一改动。
7. 后台此前只验证模型列表，无法证明真实工具、流式输出和费用能力。启用前现在通过同一原生适配器，在空的只读工作区实际调用工具及模型；现金要求各次已执行调用都有一致原始金额回执，积分要求完整真实用量。校验失败保留原配置；管理员可看到清理密钥后的具体原因。测试不扣用户钱包，消耗实际接入账号额度。
8. 原生适配器已完整返回的空回复或内容过滤错误，曾被包装成“结果未知”，丢掉真实错误且挡住可恢复空回复的原生纠错。现分别保留原始错误码、信息和结构化失败字段：已完整收到的失败响应记录为已完成的调用，而非成功任务；空回复交回原生 DSH 重试机制，新调用另建身份和费用记录。中途取消、断流等确实无法确认结果的请求仍保持未知，不能套用这一规则自动重发。

以上业务修复均有实际失败的回归测试及修复后的通过记录。一个修复前的现金建图样例因空工具身份循环被人工停止；其专用数据库快照保留。停止没有修改生产进程或记录，也没有将测试失败记成成功。

失败样例也保留：旧专业验收到 30 分钟看门狗时停止，草稿和逐次调用均已导出；连续工具验收在第 5 次模型请求没有得到可确认的结束回执，保存 3 节点草稿与 `awaiting_reconciliation` 状态，无本站扣款，也未自动重新发送原请求。私有数据库快照 `cash-specialist-stopped-diagnostic.sql`、`cash-tools-unconfirmed-diagnostic.sql` 均已保存。后续另起独立样例不等于恢复重发这笔未知调用。
