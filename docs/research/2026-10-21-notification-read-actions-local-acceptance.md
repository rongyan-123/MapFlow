# 消息全部已读与公告确认本地验收

2026-10-21 按用户确认的范围实施。消息中心和全部公告页新增“全部已读”，单条控件保留原位置，进行中重复请求去重，并同步消息、公告与铃铛状态。本轮先完成本地验证和提交，未部署，生产仍按当前发布页记录。

## 实际修复

- 消息中心一次确认账号已有公告和反馈回复，不需要逐条打开或先加载全部分页；公告页同名按钮只确认公告。提交时禁用，失败后可重试，全部已读后禁用。
- 成功确认后保留固定尺寸的禁用“已读”按钮，避免下一条公告上移。320–1440px 与横屏下操作高度至少 44px，底部全读操作保持可见。
- 快速连点可能发生在 React 渲染禁用状态之前。失败测试确认旧逻辑会提交两次；现在相同账号、相同参数的进行中请求共享一次提交，不合并不同目标。
- 已读动作、请求去重与相关缓存刷新集中到独立模块；两个页面复用同一个已读按钮。单条与全部是不同函数和接口。补齐消息中心单条读取后没有刷新旧公告缓存的问题。
- 单条失败后改用全部已读时，旧单条错误会及时清除，不会在实际已成功后继续显示失败；两处入口均有对应回归测试。
- 后端在同一数据库语句中更新两类已读状态，保留语句开始后新到的消息；跨账号隔离、重复操作及失败整体回滚均验证。旧客户端接口不变，无数据库迁移，聊天与计费逻辑不变。

未复现一次单击提交两个不同公告 ID，因此没有把“用户原始偶发连带确认”的完整根因写成已证实。本轮已稳定复现并修复的是按钮位移、同目标连点重复提交，以及两个入口缓存不同步；实际请求只包含被操作的目标。
