# 学习区完整角色库与历史开关验收

2026-10-16，基线 `main 7df7c5e`，分支 `codex/learning-role-library-20261016`，范围见[设计](../specs/2026-10-16-learning-role-library-design.md)。本轮修改前端，未部署。

## 原因与最终行为

上一轮完整角色选择只接入了酒馆。学习区仍由 `HistoryList` 从已有会话提取角色 ID，选项自然缺少没有会话的角色；原来的学习区角色切换还会 PATCH 当前会话的角色。本次删除前端的旧历史角色筛选路径，学习区和酒馆都直接渲染同一私人角色库，平台全局助手仍保持固定。

选择角色时，在当前场景、当前学习区恢复它上次选中的会话；没有会话则通过既有接口创建。其他角色的 Persona、词表、消息和画布不带入新角色；切回时恢复各自草稿。同一角色继续新建会话可沿用自身设定。已有明确属于其他角色的待确认创建请求会提示先核对原请求，不将它当成此次选择重放；原请求 ID 保留并可重试。

历史开关已移到顶部标题之前，展开和收起共用原位置，不增加侧边列。手机保留标题处的角色选择与历史抽屉；返回学习区、查看地图两个按钮进入“更多”，带明确文字，避免把角色选择挤成只有箭头。菜单中切换地图、返回聊天及重新展开画布的实际操作通过。

## 测试与构建

- 新增 15 项真实 `SceneWorkspace` + HTTP 边界测试。角色全集、独立会话、身份隔离、草稿恢复、上次会话、其他角色待确认请求、角色库读取失败等关键变更分别先失败、再实现转绿。
- 覆盖无会话角色、清空历史、新建角色立即选用、手机标题和抽屉、同名不同 ID、只读学习区、同角色继续新建、不同学习区/酒馆隔离，以及角色库读取失败后的重试。
- 针对学习区、酒馆、历史收起、发送消息、模型直达和画布的 59 项回归全部通过。
- `npm run build` 包含 `tsc --noEmit`，通过；项目没有 lint 脚本，保留原有大 chunk 构建提示。`git diff --check` 通过。
- 最终完整测试：86 个文件通过、1 个既有跳过；614 项通过、1 项既有跳过。命令 `npm test -- --maxWorkers=1 --minWorkers=1 --reporter=dot`，原登录深链 8 项也全部通过。
- 并发全量中曾有 1 项已有登录深链等待超时：停在 `正在打开页面…`，不是角色断言失败；同一测试在未修改的固定主线也复现。保留失败日志及主线对照，没有修改断言、测试超时或产品加载策略。

## 真实浏览器与接口

本地 `http://127.0.0.1:18225`，普通用户，真实 Chrome + Browser Harness；服务端与数据库均为本地预览。检查 1440、1024、768、390、320px，长角色名称、画布展开、历史收起和移动抽屉，未发现横向溢出；历史按钮始终在标题左侧，手机角色下拉宽度至少 100px，触控控件至少 44px。截图中发现并修复了原返回/地图按钮挤掉角色名的问题，没有只凭页面总宽度判定手机验收通过。

真实接口返回的全部 6 个私人角色与下拉选项逐 ID 相等；创建本轮专用测试角色后，角色库和下拉框同步为 7 项，创建角色本身未建立会话。直接在聊天页选择新角色，创建当前学习区的独立空会话；来回切换后仍使用同一记录、草稿分别保留，原聊天图、原 Persona 与原画布逐项相等。没有点击收费模型发送。

第一次原生键盘选择脚本遇到聚焦刷新后的角色排列变化；改为聚焦后读取当前选项顺序，完成相同操作和结果核对，没有更改产品角色数据来配合脚本。测试结束只清理本轮新建的角色和会话，原角色 ID 集合、学习区会话 ID 集合均恢复，所有原记录保留。生产和 Codex 会话不受影响。
