# MapFlow 邀请激活账号前端设计

- 日期：2026-08-10
- 状态：依据已批准的产品决策实施
- 后端契约：私有 `mapflow-server` 的邀请码身份 v1
- 明确不包含：AI 生成、API Key、积分、支付、短信/邮箱验证码、自动找回密码

## 1. 目标与不可突破的边界

1. 匿名访客无需注册，继续完整浏览当前公开技能树；
2. 只有后端能力接口报告身份功能开启时，页面才展示登录和注册入口；
3. 注册表单收集用户名、8～128 位密码、确认密码、6 位大写邀请码，以及至少一种未验证联系方式；
4. 注册成功即由后端创建并激活账号、分配永久玩家 ID、设置 HttpOnly Session Cookie；
5. 清除 Cookie 只让当前浏览器退出，账号激活状态不受影响；
6. 页面不保存密码、邀请码、Session token，也不使用 localStorage 保存 CSRF token；
7. HTML、React state、F12 和请求体全部视为不可信。前端只显示服务端结果，不发送或判断 `activated`、`role`、`credits`、资源 owner 等授权字段。

## 2. 交互方案选择

评估过三种方式：

1. **顶栏入口 + 模态框（采用）**：对现有技能树布局侵入最小，匿名用户打开网站就能看到图；登录和注册是随时可关闭的辅助流程。
2. **独立登录/注册路由**：URL 清晰，但会把用户从技能树带走，还需要增加路由依赖和返回逻辑，首版收益不足。
3. **常驻账号侧栏**：账号信息更醒目，但会挤压已经较密集的节点详情区域，在小屏上尤其明显。

采用方案 1。顶栏右侧新增一个紧凑账号入口：匿名时显示“登录 / 激活账号”，已登录时显示用户名和玩家 ID，并提供退出按钮。能力关闭时不显示虚假的可用入口，技能树保持原样。

## 3. 模块边界

```text
App / existing skill-tree UI
        │
        └── IdentityAccess (展示与交互状态)
                 │
                 ├── IdentityDialog (登录/注册表单)
                 └── identityClient (唯一 HTTP 契约层)
                            │
                            └── same-origin /api/auth/*
```

- `identityClient`：请求能力、当前会话、注册、登录和退出；解析稳定错误信封；所有请求使用同源 Cookie；不依赖 React。
- `IdentityAccess`：通过 React Query 管理能力、会话和 mutation；认证成功后只把公开账号与当前 CSRF token放在内存缓存。
- `IdentityDialog`：负责字段、客户端体验校验、pending 状态和安全错误展示；客户端校验不能替代服务端校验。
- `App`：只在顶栏挂载入口，不知道密码、邀请码、Cookie 或请求细节。

## 4. 数据流

### 4.1 启动

1. 请求 `GET /api/capabilities`；
2. `registrationEnabled=false` 时停止，不请求身份路由，匿名技能树照常工作；
3. 开启时请求 `GET /api/auth/session`；401 表示匿名，不作为页面错误；
4. 其他网络错误只影响账号入口，不阻断技能树。

### 4.2 注册与登录

- 注册只发送 `username`、`password`、`invitationCode`、可选 `email`、可选 `phone`；
- 登录只发送 `username` 和 `password`；
- 成功响应包含公开账号和 CSRF token；Cookie 由浏览器接收，JavaScript 无法读取；
- 密码与邀请码在请求完成后随表单关闭而清空；不写日志和持久存储；
- 400、401、403、429、503 都显示后端安全文案；429 明确提示稍后再试。

### 4.3 退出

退出请求携带内存中的 `X-CSRF-Token`。成功后清除身份查询缓存。请求失败时保留当前显示并提示，不伪装为已经在服务器退出。

## 5. 表单规则

- 用户名：2～24 个字符；前端提供长度提示，完整字符 allowlist 仍由后端裁决；
- 密码：最少 8、最多 128，允许粘贴，不强制大小写或符号；
- 确认密码必须一致，但不会发送给后端；
- 邀请码：输入时转大写，只允许最多 6 个 `A-Z`，提交时必须恰好 6 位；
- 邮箱或手机号至少填写一个；手机号允许 8～15 位数字和可选前导 `+`；
- 浏览器 autocomplete 使用 `username`、`current-password` 和 `new-password`，兼容密码管理器。

## 6. 安全与可访问性

- 模态框使用真正的 `<dialog>` 语义或等价 `role="dialog"`，具有标题、关闭按钮、Escape 关闭与明确 label；
- 登录按钮不会承载权限判断。即使用户用 F12 打开按钮或篡改页面，后端仍独立校验邀请码、密码、Session、Origin 和数据库状态；
- 不在错误中推断“用户名存在”“邀请码有效”等细节；
- 不把 CSRF token 放入 URL、DOM data attribute 或持久存储；
- 不添加第三方认证 SDK、分析脚本或远程资源。

## 7. 测试与验收

新增 Vitest 测试层：

1. `identityClient` 只发送允许字段，携带同源凭据，正确处理 401、429 和错误信封；
2. 退出请求必须包含当前 CSRF header；
3. 能力关闭时不出现账号入口且技能树正常；
4. 注册表单拒绝短密码、非六位邀请码、联系方式全空和密码不一致；
5. 成功注册/登录后显示服务端玩家 ID，退出后回到匿名状态；
6. `npm test`、TypeScript 检查和 Vite production build 全绿。
