# 学习区角色库直达与历史开关位置

沿用已经确认的「角色库直接选择、每个智能体保留独立会话、桌面和手机可用」规则，修正学习聊天与酒馆行为不一致的问题。历史开关移到页面顶部标题之前，与其控制的左侧历史栏靠近；收起后仍可从原处展开，不增加列或第二行工具栏。

学习聊天和酒馆的角色选择都直接使用私人角色库返回的完整角色集合，包括尚未创建会话的角色、同名但不同 ID 的角色、新建及导入角色。平台全局助手继续固定，不进入私人选择列表。

选择角色时，只在当前场景、当前学习区中查找该角色的会话：优先恢复上次选中的记录，否则打开最近记录；没有记录则通过既有接口新建。新建其他角色的第一条会话不继承当前角色的 Persona、词表、消息或画布；学习区工具开关按既有默认规则处理。对话草稿按会话保留，切回后恢复；再次新建当前角色的会话仍允许沿用该角色的个人会话设置。

移除从历史会话推导角色下拉选项的旧路径。历史消息列表仍展示所选角色的会话，提供查看全部历史的入口；已移出角色库的角色不再可新建，其旧记录保持可读。角色库加载或创建失败时显示错误，保留原会话；只读学习区不得新建或切换角色。复用现有创建请求 ID 与失败恢复契约，不改后端接口、数据库、计费或全局助手。

## 实施与验证

1. 使用既有 `SceneWorkspace` + HTTP 边界测试复现「学习区角色库有角色、下拉框却没有」；确认失败，再修改页面和列表的数据来源。
2. 按测试 → 失败 → 实现 → 通过逐项验证学习区角色选择：已有会话恢复、未使用角色创建、草稿/身份隔离、同角色新建、不同学习区与酒馆隔离、空历史和移动端入口；保留酒馆和全局助手回归。
3. 将历史开关放入 `PageHeader` 的可选标题前插槽，普通页面不出现该控件。浏览器确认位置、展开/收起、画布实例和输入草稿保留。
4. 运行完整前端测试、TypeScript/生产构建和差异检查；用真实本地 API 检查 320、390、768、1024、1440px、长名称、角色库全部选项和画布展开，截图验收。
