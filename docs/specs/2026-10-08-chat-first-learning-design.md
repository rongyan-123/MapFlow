# MapFlow：聊天优先的“我的学习”重构审计与设计草案

日期：2026-10-08。

状态：**完成源码审计与设计准备，等待用户确认实施范围。没有修改产品代码、迁移数据库或部署此重构。**

## 1. 本轮以什么为准

用户最新要求是两个主业务入口：**公共书库、我的学习**。“我的学习”直接进入 Agent 对话，不先要求选择地图或导入角色卡。地图是按需检索的学习资料；角色卡是可选择的智能体；教学画布是可展开的工具。

附件《MapFlow 四界面与学习区重构交接方案》作为参考方案，不把其中的交接指令当成本轮授权。它核对的是旧分支，本轮重新核对当前 main。

| 附件安排 | 本轮审计结论 |
|---|---|
| 公共书库、我的地图、学习聊天、独立酒馆四个主界面 | 被最新的两个主入口替代；我的地图保留为“我的学习”里的资源视图，角色聊天并入同一个对话系统。 |
| 必须先选择一张地图对应的学习区 | 不采用这个前置条件；无地图、无角色卡也能新建空对话。 |
| 学习对话只能读固定的一张地图 | 不符合最新要求的“AI 列出自己的技能树”；改为账号内按需发现与阅读，修改仍须明确目标和确认。 |
| 独立酒馆永远不能读个人地图 | 不再设独立酒馆场景权限；由每段对话的工具授权决定，纯角色聊天可以关闭地图读取。 |
| 角色共享、历史筛选不切换当前角色、导入不清空对话 | 保留。 |
| 按需检索，不注入整树和全部历史 | 保留并作为性能、用量验收项。 |
| 保留地图、笔记、进度、支付、辅助入口及服务端权限校验 | 保留。 |
| 把工具错误简化成对用户友好的提示 | 普通界面使用安全文案；有权执行的 Agent 仍收到可纠正的结构化工具错误，持久化诊断继续保留。不能因为改文案而截断纠错链路。 |

本文的默认行为和权限细节属于**本轮推荐方案**；文档审核通过才表示接受这些实施安排，不能把它们说成过去已逐项确认。

| 会话图、消息分支、计费、工具诊断已有统一存储 | 沿用同一套记录，旧酒馆和地图聊天无需搬进另一套聊天数据库 | 后端 `src/tavern/store.rs` 等 |
| 部分错误组件直接展示 error.message，仍有内部服务文案 | 改到的新入口采用统一安全提示，同时审计其关联错误出口；内部诊断不能跟着丢失 | 前端 `TavernUi.tsx`、`TavernPage.tsx`、`ConversationPane.tsx` |
| 加入公共地图会创建账号自己的私人副本 | 保持现有语义；操作自己的副本不能改变发布者的公共原图 | 后端 `src/adapters/postgres/tree_library_store.rs` 的 `add_public_tree` |

## 3. 方案选择

1. **推荐：两主入口、统一会话、可引用地图与可展开画布。** 与最新要求一致；复用聊天引擎，但需要拆分前端状态、补齐目录工具和资源授权。
2. 只给现有酒馆换成 ChatGPT 样式。改动小，但聊天仍被地图绑定、角色筛选仍与切换耦合，无法满足自主查找地图的要求。
3. 沿用附件四界面和强制学习区。组织边界明确，但增加用户先选区的步骤，也与最新的两个入口相冲突。

实施采用方案 1，不建立强制“一图一学习区”的新业务层，不另造第三套 Agent 或聊天存储。

## 4. 页面与关键交互

### 4.1 桌面布局

```text
┌────────────────┬────────────────────────────────────────────┐
│ 公共书库        │ 我的学习 / 当前对话                         │
│ 我的学习        │ 当前智能体 ▾  导入角色卡   我的地图   教学画布 │
│                │ 引用资料：[地图/节点索引 ×]  [+ 添加资料]     │
│ ＋ 新建对话     ├────────────────────────────────────────────┤
│ 智能体：全部 ▾  │                                            │
│   新增 N        │             对话 / 空白欢迎区               │
│ 最近对话        │                                            │
│ · 对话主题      │                                            │
│ · 对话主题      ├────────────────────────────────────────────┤
│                │ 模型与接入方式   参数                       │
│ 辅助菜单 /账号  │ 输入问题……                          发送   │
└────────────────┴────────────────────────────────────────────┘
```

这是一份功能位置草图，不把截图中的 ChatGPT 名称、品牌、订阅入口或无关功能照搬。

- “新建对话”是学习页的主要创建操作；创建角色、导入角色、展开画布分别放在命名清楚的次级入口，不共用一个含混的加号。
- 默认不显示地图渲染器或画布；已有对话呈现居中、适当限宽的聊天阅读区。
- 展开画布时沿用画布在左、聊天在右的教学布局，可拖动分隔线；收起时用短过渡并支持减少动态效果。画布工具权限与画布可见性分开：收起不会撤销授权或清空内容。
- “我的地图”打开学习页内部的资源列表；点击地图可进入完整地图视图，提供清楚的返回对话入口。它不是第三个主业务导航，也不长期占据聊天旁边。
- 隐藏时重型地图与画布不维持连续渲染循环；返回依靠已保存的视口与资料恢复。拖动聊天宽度不能触发整棵地图反复布局。
- 输入区保留模型、接入方式与单独的“参数”按钮；不把所有参数塞进总配置弹窗。平台/自用模型偏好继续按账号记忆。
- 公共书库保留搜索、筛选、公开预览及加入个人库；不能在重构导航时再次丢掉搜索筛选。

### 4.2 新建与恢复对话

- 新用户进入“我的学习”直接看到空输入区，不要求先建图、充值、导入角色或选择学习区。发送时仍遵守实际模型配置、登录态和既有余额规则。
- 默认智能体暂定名 **MapFlow 助手**，使用现有聊天模型接入，不是新增模型服务。默认角色配置只描述学习和教学职责，实际工具权限由服务端决定。
- 点击“新建对话”打开真正空的消息记录，不自动请求模型、不自动收费、不继承上段对话的地图和私人会话设定。新会话默认 MapFlow 助手；显式“用这个角色新建对话”可带指定角色。
- 默认助手按账号幂等创建或取得，不能并发生成多个默认角色。已有自动创建的地图学习助手保留，不能批量删除或合并其历史。
- 角色卡开场白仍作为角色资产保留，但新空对话不自动插入开场消息；旧对话已有开场白保持原样。
- 初始标题为“新对话”；首次成功发送后可用首条用户消息生成本地、限长标题，不额外调用付费模型。用户手动改过的标题不覆盖，切换角色不改标题。
- 左侧显示当前账号全部历史，按最近活动排序，不按正在浏览的地图强制隐藏会话。首次进入可恢复仍有权限的最近对话；点“新建”则明确进入空会话。
- 刷新与旧链接恢复以服务端会话 ID 为准；本地偏好不能把另一个账号的会话或模型凭据带过来。

### 4.3 智能体筛选、角色切换、导入提示

三个动作保持独立：

| 动作 | 结果 | 不产生的副作用 |
|---|---|---|
| 左侧“智能体：全部”选择某角色 | 筛选最近会话列表 | 不切换已打开对话、不换当前发言角色、不创建对话、不调用模型 |
| 点击某条历史对话 | 打开这条会话及其已保存配置 | 不因角色库更新而重写旧消息 |
| 对话顶部选择“使用此角色” | 显式更换这段对话的当前角色，保留消息与标题 | 不自动发送或收费 |

筛选默认“全部”，在当前页面内保留选择；重新进入的默认仍为“全部”。第一版按会话当前角色归类，曾经切换过角色的旧消息仍保留原作者标记。已隐藏的角色对应历史可在“全部”中找到。

导入和自创入口共用角色库流程；无论从顶部还是智能体菜单导入，成功后：

1. 角色进入当前账号角色库，显示名称和可选的“使用”操作。
2. 不覆盖当前角色、会话、草稿、地图引用或聊天历史。
3. 左侧智能体选择处显示“新增 N”或红点，打开菜单后清除；新导入角色容易找到。
4. 新增提示按账号保存，导入失败不加计数；另一账号看不到这份提示。

角色编辑、重命名、隐藏/删除原有能力继续保留；旧会话已有的角色快照不被新卡内容偷偷替换。将编辑应用到当前对话仍须明确操作。

### 4.4 知识地图作为可引用资料

- 用户可从“添加资料”选择自己的地图，加入的是稳定 ID、名称及可选节点 ID，**不是完整树、所有笔记或整段历史的文本拼接**。
- 推荐支持一段对话引用多个地图索引。没有引用也能聊天；引用是优先阅读线索，不是唯一可读地图的白名单。可读范围由下节的账号权限决定。
- AI 需要找资料时可分页列出或搜索当前账号地图，再读取相关节点、笔记片段、进度和关系。现有颗粒化阅读方式继续使用；不能一次遍历所有树或强制全量读取。
- 系统按真实工具结果展示实际查阅的资料名称，与用户固定的引用区分；不能凭 AI 自称“已经读过”写入可信引用状态。
- 从地图节点点击“向 AI 提问”时进入对话并带待发送的节点引用，不自动发送或收费。若有当前对话，提供“引用到当前对话”与“新建对话学习”的明确选择；没有当前对话则创建空对话。输入草稿不能被静默覆盖。
- 地图名称更新不改变稳定 ID；资料被删除、访问撤销时标明引用失效，不静默替换另一张地图，保留仍可访问的对话记录。
- 从公共书库加入的是现有私人副本；公共预览不授予修改公共原图的权限。

## 5. 工具与数据权限：本轮推荐基线

统一的是对话引擎和角色资产，不是给模型数据库访问权。

| 能力 | 新学习对话的推荐默认 | 执行边界 |
|---|---|---|
| 列出/搜索我的地图 | 开启，可在资料设置关闭 | 只返回当前账号有权使用的地图目录，分页；不读所有正文 |
| 阅读地图、节点、笔记、进度 | 与上述读取授权一致 | 按明确问题、目标和分页按需取；每次执行由服务端复核所有者和可读性 |
| 提出地图/笔记/进度修改 | 新空对话默认关闭；可单独开启 | 开启后也只能提出具体目标修改，由现有确认流程批准后提交 |
| 删除、覆盖等破坏性修改 | 不自动执行 | 保留逐次确认，目标地图及变更内容必须明确 |
| 绘图 | 沿用可开关的“允许 AI 绘图”授权 | 只操作这段对话的教学画布；不因读取地图开启而自动获得绘图授权 |
| 读取其他会话全文 | 不提供 | 选择智能体和列出历史仅供 UI；不把其他对话自动注入模型 |
| 账号权限、支付、密钥、管理员功能 | 不提供工具权限 | 只引导用户使用已有界面；管理员账号聊天也不自动取得这些工具 |

新建对话默认允许读取自己的地图是本轮待确认的产品安排，对应用户要求的自主发现能力；界面在资料设置中清楚显示。纯角色聊天随时可以关闭。

旧对话迁移时**不扩大原有授权**：开启了树工具的沿用其既有权限；关闭的保持关闭。旧的单图阅读范围先保留为“仅关联地图”，用户显式允许“我的地图”后才能跨图发现。新老对话使用同一引擎，范围可以不同。

附加索引不会把其他账号、已撤销权限或未授权的资料变成可读资料。模型提供的地图 ID 只能当目标候选，由登录态取得账号身份并验证。角色卡内容、地图正文及工具返回数据不允许改变授权。

修改确认必须绑定账号、会话、目标地图、具体变更及对应版本；确认到实际提交间重新检查授权和版本。不能继续依靠“当前浏览地图”或可变的 UI 选项决定最终写入目标。

增加或移除引用、切换角色、修改工具范围后，更新请求配置指纹与可用工具集合；旧缓存不能继续带上已撤销资料。对话已有的正常历史不会因此删除。

绘图与地图修改的现有提交语义要如实保留：画布预览在回复成功时持久化，地图批准修改可能已经提交。发生后续生成错误时，不能笼统显示“一切未改变”；依据真实结果显示状态。

## 6. 会话运行、用量与失败处理

- 继续复用消息分支、续写、重试、流式缓冲、模型参数、用量、实际现金结算和诊断记录，不在这轮重写定价或充值匹配规则。
- 每个生成动作绑定账号、会话、分支和请求 ID。切换历史、打开地图或书库后，结果仍归属发起对话，不插入新对话。
- 把运行请求的状态管理放到不会因面板切换立即销毁的页面控制层；消费流和更新缓存也按请求归属校验。保持现有会话并发与重复请求规则，本轮不新增账号级并发上限；是否正在生成及取消入口明确归属具体对话。
- 刷新后以已持久化记录恢复；不承诺关闭浏览器后未持久化的在途文字一定不丢，也不把本地草稿当服务器保存成功。
- 保持前一轮规则：现金余额大于 0 才开始新的平台生成，完成后按真实费用结算，可成为负余额；失败按既有结算结果呈现；不重新加入“最高输出预留不足”发送拦截。
- 工具失败保留工具名、阶段、校验字段、实际错误及关联请求，走已统一的持久化渠道；已授权 Agent 能收到结构化错误并纠正，不用新提示词掩盖问题。
- 普通 UI 通过已知错误类型映射友好提示和请求编号；原始异常、内部地址、密钥等不直接塞进普通错误弹窗。未知错误统一兜底，不能推断是否扣款或保存。
- 不把技术诊断日志作为普通学习知识库索引。已有诊断读取工具只保留它本来的账号/会话边界与必要信息处理。

## 7. 实现范围与历史兼容

### 7.1 前端
