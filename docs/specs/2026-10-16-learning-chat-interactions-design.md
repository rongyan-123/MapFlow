# 学习聊天交互修复

用户已明确要求收起历史栏、显示自己发送的消息、从输入框直接选择模型，并要求完成后结合实际 MapFlow 节点解释上下文与缓存。本轮延续已批准的桌面及手机 UI 改进，在上一轮完整候选版本上隔离开发；不发布、不改聊天记录或计费规则。

## 行为与边界

- 顶部历史按钮常驻，桌面显示明确的展开/收起状态。收起时同时移除历史栏和调整宽度的分隔条，释放整列空间；聊天、草稿和画布不卸载。小于 1024px 时该按钮打开历史抽屉，不增加独立栏位。全局助手保持其专用页面，不增加历史入口。
- 当前回复请求中的用户输入立即显示在消息列表，位置在本次助手输出之前。请求尚未确认或失败时说明状态，不虚构已落库消息；已有请求身份用于恢复和去重，不以文本相同判断重复。完成后历史尚未送达时仍保留用户问题，历史到达后只显示已保存的一份。重新生成和继续回复不增加用户消息；切换会话不能串入其他会话的请求。
- 输入框的模型按钮与普通配置入口分开：前者直接进入“模型接入”，后者仍从原配置首页进入。保留草稿。学习聊天、酒馆共用修复，全局助手现有模型设置直达行为保持。

## 步骤与验证

1. 从真实页面与 HTTP/流式响应边界复现缺失的发送消息和错误模型入口；新增测试先运行确认失败。历史开关验证桌面状态、释放空间与手机抽屉行为。
2. 逐项最小实现并运行对应回归。覆盖发送中、结果已完成但历史刷新失败、成功刷新去重、恢复原请求、相同文本的新请求、继续/重新生成和切换会话。
3. 跑完整前端测试、类型检查和生产构建，自审 diff。真实浏览器检查 320、390、768、1024、1440px，覆盖长标题、展开画布、收起历史、手机抽屉、输入及模型选择；保存截图。
4. UI 验收后使用 MapFlow skill 只读查询进度和目标地图节点。核对后端上下文构建、工具按需读取、压缩恢复、前缀排列及真实用量字段，以源码和可获得的凭证区分事实与推断，不将低费用直接归因于缓存。

纯 UI 与浏览器检查不调用收费模型。不在本轮清理 Codex 会话、工作区或历史。
