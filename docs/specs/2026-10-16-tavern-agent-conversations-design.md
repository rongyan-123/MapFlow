# 独立酒馆的智能体与会话选择

用户明确确认：角色卡对应独立智能体，每个智能体可以新建多段会话；切换智能体时，各自的记录独立，全局助手仍使用其独立记录。基线为 `main f018a4fc15babeef3a83c42e0dff06d318ee7c85`，复用现有开发工作区，分支 `codex/tavern-agent-conversations-20261016`。

## 行为与界面

- 酒馆原“全部角色”实际仅按历史中的角色 ID 筛选，不能选择尚未聊天的角色。改为直接列出完整私人角色库，使用 ID 区分同名角色；创建、导入、重命名或删除后及时更新，平台固定助手不进入此列表。
- 选择智能体时，打开它上次使用且仍存在的会话，否则打开它最近创建的会话；没有会话则为该智能体新建。绝不对当前其他智能体的会话调用换角色接口，也不复制其消息、Persona、词表或画布。旧记录不迁移或改写。
- “开始新对话”只为当前智能体新建；默认会话列表只显示当前智能体，并保留明确的“查看全部会话”入口，方便访问旧记录和已移除角色的快照。
- 创建或导入只保存角色库，不悄然替换正在聊天的智能体。关闭弹窗后，新增角色立即可从聊天界面选择；角色库中的“使用角色”也走同一独立会话流程。
- 手机和平板在聊天顶栏直接提供智能体下拉选择，保持现有一行顶栏；手机历史抽屉同样显示完整角色库。控件至少 44px，高度和长名称在 320px 窄屏检查。
- 未发送草稿按会话区分并在本次页面访问内保留；切换后不把其他智能体的草稿带过去。切换、创建和保存期间禁用会冲突的操作；失败保留原会话并显示可重试错误，不假装切换成功。

本次修改前端选择、列表和状态管理，复用现有按账号/场景/会话归属的接口。全局助手和学习聊天保留各自既有入口与行为，计费和后台执行协议不变。
