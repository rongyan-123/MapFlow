## 建议的技术选择

| 方案 | 效果与代价 |
| --- | --- |
| 推荐：现有 React/Vite 工具链下重写所有页面、外壳和前端请求组织 | 全站新界面；地址和后端契约可以直接衔接；不会同时引入框架、部署和数据库迁移。 |
| 整个前端含协议一起重新定义 | 也能重做，但需要同时调整服务器、历史会话、恢复与结算契约；超出当前 UI 优先范围。 |
| 换成另一个框架并重写 | 外观同样可以实现，却增加构建、运行与迁移变量；现有问题没有证据表明来自 React/Vite。 |

选择第一项。所有页面的 UI 与页面控制器重写；原请求模块收敛到独立 api/ 层，保留经过验证的服务器字段、权限与幂等契约。最后移除原 App 内的页面布局、Portal 外壳、重复请求封装和被替换的旧组件，产品只保留新入口。并行开发期可保留旧页面作为对照，正式切换后不保留两套生产前端。

页面地址与服务器 API 是两层：/assistant 等地址可以保持不变；新前端请求模块仍调用既有 /api/...。不为了换 UI 改后端路径、响应格式或幂等身份。

## 全站视觉与交互

采用安静的中性色背景、低饱和绿作为主色、清楚的正文对比度；浅色和深色共用同一套设计变量。用户可以选择默认主题。正式实现遵循系统减少动画设置，不依赖发光、过量渐变和大段装饰来填充界面。

- 手机只有一条 52px 内容顶部栏；浏览器顶部不预留额外假状态栏。若独立安装模式需要安全区，由外壳统一负责，页面不重复加安全区和顶部偏移。地址栏变化、键盘出现和 visualViewport 缩放必须单独验证。
- 手机书库、我的地图等普通页面使用四项底部导航；聊天、地图和画布采用单个主要工作区，聊天输入时底部导航收起，导航仍从顶部菜单可达。
- 桌面使用统一主导航；上下文列表按空间展示或进入抽屉，不能强行挤压聊天。1024px 需验证；侧栏扩宽、长模型名和地图展开时，次要操作依次收进菜单。
- 书库默认给用户地图列表、搜索和分类；选中后再看路线。默认状态不展示空画布再让用户寻找另一个入口。
- 空聊天有四个可点任务：创建地图、规划节奏、挑选地图、解释难点。点击只填入草稿，不自动发送或收费。该部分是本轮展示的引导布局，具体入口任务可随用户反馈调整。
- 地图生成结果标题占独立区域；手机按钮在标题下方同排，长标题不被两个按钮挤成一窄列。
- 配置五页共用一个外框；桌面 820×650，较小窗口适配视口；手机为可视区域内完整配置页，标题与关闭固定、选项可达、正文内部滚动。切页不改变外框大小。
- 后台手机使用分区选择器与记录卡片，普通管理操作不依赖在宽表格上来回滑动；桌面仍使用可扫描的表格。

## 新前端的模块边界

```text
src/app/         路由表、页面入口、身份门禁、地址兼容
src/ui/          设计变量、按钮、输入、弹层、导航、响应式列表
src/api/         身份、地图、会话、Agent、额度、管理；统一 HTTP 和事件解码
src/domains/     业务类型与页面控制器；每个领域负责自己的查询和交互状态
src/pages/       首页、身份、助手、书库、地图、学习、酒馆、额度、设置、后台
```

依赖从页面 → 领域控制器 → API；ui/ 不导入领域或 API。api/ 不导入酒馆组件、页面或 React。助手、学习和酒馆组合共用 ConversationWorkspace 展示组件及执行控制器，不再继承一个巨型酒馆页面。

服务器是已完成消息、地图和费用的来源。发送草稿与临时流式增量作为临时状态，完成后用服务器结果收敛；不另建一份长期消息数组。模型目录、账号和额度状态有统一来源，切换账号清除前一个账号缓存。BYOK 密钥不作为普通 UI 偏好持久化。

地图渲染和教学画布分别封装，并按需加载 React Flow / Excalidraw。首页不必加载后台和画布，后台各分区也按需加载。保持现有 React、Vite 和测试工具，不趁重做 UI 升级无关依赖。

## 必须保留的协议行为

- 所有写请求携带原 CSRF 与身份信息；错误码、请求 ID、取消与失效登录的处理统一。
- Agent 使用现有 execution ID、clientActionId 与事件 sequence。连接恢复只重新附着已有执行；结果未知时不自动再发一次收费请求。继续、重新生成与消息编辑保留已有分支语义。
- 会话删除仍遵循服务器活动执行检查、画布待保存/保存中/失败处理、默认会话缓存和删除最后一条后刷新仍为空的规则；创建重放被终止时，清除待重试状态，新的主动创建使用新 ID。
- 画布草稿、地图版本、进度、发布和角色编辑沿用现有版本/哈希保护。切页和卸载不能提交已经删除的旧画布。
- 费用与到账状态以服务器回执为准。重新设计额度页不改动收款服务、计划任务、账本或结算逻辑。
- 未返回数据时展示真实空状态或错误；示例地图和模拟金额只用于独立设计稿，不能充当正式生产数据。

## 与旧生成器删除的关系

新界面以全局 Agent 承担创建地图入口。旧生成器后端代码、任务进程、额度与历史会话读取的退役需要独立核对消费者；BYOK 模型目录等共用接口不能随旧生成器模块误删。现有地图、历史对话、结算与 Codex 会话均保留。该退役项在全站前端确定后，再确认具体删除清单并实施。
