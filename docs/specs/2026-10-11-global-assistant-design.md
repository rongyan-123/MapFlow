# MapFlow 全局助手与平台模型配置设计

初稿日期：2026-10-11；本次修订：2026-10-12。状态：修订稿 `29ef923` 已经用户审阅并同意实施，长线任务已开启。初稿 `6bed052` 经用户审阅后补齐执行、恢复、结算和验收规则；本文件记录设计，实施进度见对应执行计划和验证记录。

用户补充的明确规则：本站不设置工具次数、Agent 步数等人为执行上限；费用长期无法核对时一直保留并提醒管理员，不自动免收或结案。

## 1. 已确认的边界

用户确认统一 Agent 执行的方向，并补充两点：全局助手新增为默认界面，原来的技能树加聊天学习界面继续保留；平台模型属于可替换的适配层，管理员能够在后台切换。

本设计在这些具体事项上优先于 `2026-10-08-four-interface-learning-design.md`：原四个业务页面保留，新增全局助手入口；此前“不增加第五个主界面”“全局助手只放在学习区选择层”不再适用。其他既有角色、历史、学习区权限、导航和计费规则继续沿用。

目标是让用户从一句自然语言请求开始查找地图、创建技能树，再进入原有学习区；让建图与聊天复用 Agent 执行、工具结果、错误诊断和用量记录，减少并行维护的生成流程。

## 2. 界面与跳转

- 左侧增加“全局助手”，保留公共书库、我的地图、学习聊天、独立酒馆及辅助入口。手机端继续使用覆盖式抽屉。
- 登录后无明确目的地的默认入口打开全局助手，直接可输入。直接访问地图、学习区、酒馆、钱包等链接时保留其目的地；公共产品首页仍可单独访问。
- 复用现有管理场景的默认角色、会话和角色选择器；进入页面不触发付费生成。已存在的管理助手历史可以继续打开，不复制一套聊天数据。
- 用户说“开始学习这张地图”时，助手可以查找明确的个人地图，返回带标题的“进入学习”卡片。卡片由服务端返回的地图、学习区标识生成，前端使用受支持的站内路由。
- 用户点击卡片后，幂等取得或创建该地图的学习区，切换到原来的技能树加聊天界面；已有学习对话按原规则恢复。可在手机端提供突出显示的导航入口作为补充引导。
- 跳转失败留在当前对话并允许重试；不切到别的地图。进入学习区不自动发送消息、重新生成地图或收费。
- 学习区列表、区内角色、多会话、地图与画布切换及拖宽继续保留。原“打开管理助手”入口改为打开同一个全局助手页面。

全局助手用于跨个人地图的任务和管理；学习区聊天围绕一张明确地图持续教学。两者共享角色库和聊天基础设施，分别保留会话归属。全局助手不会默认读取所有学习聊天全文，也不会把管理对话自动合并进某个学习区。

## 3. 统一执行与技能树创建

### 3.1 对话、执行与草稿

术语定义见根目录 `CONTEXT.md`。以下边界在界面、执行记录与结算中保持一致，不再用“一次任务”指代三个不同对象。

| 对象 | 生命周期 | 模型与结算边界 |
|---|---|---|
| 对话 | 同一场景中的多轮交流，可有多个分支和草稿 | 不是一次扣费单位；打开或恢复对话不产生模型调用 |
| Agent 执行 | 一次明确发送、重新生成或显式继续；内部可以多次调用模型与工具 | 开始时固定模型、资金通路和费率；成功执行的实际调用费用按执行汇总，最多入账一次 |
| 地图草稿 | 跨执行保存的学习方案，直到发布为正式地图或用户明确放弃 | 草稿本身不收费、不绑定永久模型；同一草稿可在后续执行中换模型，但一次发布只得到一张正式地图 |

例如，用户分三轮补充需求，每轮各有一次执行，各轮成功后分别结算自身实际调用；三轮可以修改同一份草稿。上一轮完成或停止后，下一轮允许改变模型及资金通路。一次执行内部的断线恢复、模型分段续写或工具纠错，不产生新的执行身份，也不会再次收取已入账费用。

“执行恢复”与“草稿继续”分开：前者沿用未结束执行及其模型、费用记录；后者在已停止或已结束执行的草稿上开始一次新执行，只计算这次新增调用。相同用户文字不作去重依据，重送同一个操作标识才是同一执行。

### 3.2 共用机制与权限边界

最终全局助手、原学习聊天和独立酒馆，以及其中的现金、积分、自填 Key 请求，都使用同一套 DSH 执行、工具结果和恢复机制。界面保留，模型差异由适配器处理；服务端负责数据访问和最终写入，模型负责理解需求、决定步骤及根据工具结果调整。

共享执行不等于共享全部工具：全局助手可以定向管理本人地图；学习聊天限定当前学习区；独立酒馆继续不获得私人学习资料权限。自填 Key 的费用由用户自己的模型账户承担，不进入本站现金或积分账本；没有费用字段不应因此拒绝一个完整的自填 Key 回复。

### 3.3 草稿、批量操作与发布

用户请求建图后，助手在当前对话中确认必要需求，然后建立可持久保存的草稿，分批补充阶段、节点、关系与教学资料。草稿工具逐步返回已保存内容的简要结果，避免每步重复返回整棵树。

草稿支持批量添加、更新节点及关系；一个模型工具请求可以提交一个完整批次，不要求每个节点单独调用。批次先校验、再整体提交；记录操作标识、参数摘要与草稿版本，重送同一操作返回原结果，不能追加重复节点。传输需要分块时，各块有可追踪的状态，不能把已保存的一半当作整批失败后重新插入。

最终提交仍校验必要的结构条件，例如节点标识唯一、关系目标存在、没有非法环、当前账号有权写入。可纠正的问题返回具体位置、原因和当前版本，让 Agent 修改同一份草稿后继续。无需增加固定的多阶段模型流水线，也不把旧生成器包成不可见的黑箱工具。

最终提交工具先保存经过校验的待发布版本和发布意图。正式地图、结果卡片与结算记录按第 4 节共同入库；模型声称完成或输出正文 JSON，不能代替实际保存结果。同一草稿的发布标识唯一，重复发布返回已经创建的地图。

以建图为目标的执行，成功条件是经过校验的地图正式保存；最后一段自然语言总结不是必要条件。模型未提交有效版本时只保留草稿，不声称生成成功。最终卡片提供“查看地图”和“进入学习”，其目标由已保存记录确定。

已有地图的修改、笔记和进度继续按原有明确目标、变更确认及版本规则执行；新建地图不能借机覆盖已有地图。地图创建工具不授予支付、密钥或管理员能力。

### 3.4 本站不设置人为执行上限

取消本站工具总次数、Agent 步数、纠错或续跑次数、总执行时长、任务费用及统一输入/输出 Token 的硬上限。不能把 8 次、16 步、900 秒替换成一个更大的常量，或增加另一种“阶段预算耗尽”的失败。Rust 调用、DSH、工具分发、协议校验和前端共同遵守，不能只改一个常量。

执行可持续进行到模型自然完成、用户明确停止或发生确实不可继续的故障。批次和进度在执行过程中保存，不为了满足固定步骤数切断执行再要求用户重试。权限、真实余额规则、版本和数据结构校验继续有效，它们不是次数预算。

模型自身的窗口和单次输出容量仍是实际协议能力。将到窗口边界时整理上下文；单次输出截断时保留已完成内容和草稿，从检查点继续同一执行，不能把单次截断直接判为整项任务失败。半截 JSON 不执行写入，先让模型补全或重新提交相应操作。

现有单条输入 8 KiB、历史 8/16/32 KiB 等统一硬拒绝或整轮丢弃规则，应改为完整保存、按目标窗口整理和按需读取。分页、分块及缓存回收用于传输和内存管理，不能限制用户的整项任务规模或让后续页面无法继续读取。

连接健康检测、所有权续租和服务方限流可以触发等待或恢复，不构成整项执行的时长或次数上限。可恢复故障使用等待和退避，不因重试次数到了就丢失任务；凭据失效、撤权等确实不可继续的故障明确保存原因。资源忙时排队，不能因工具或模型调用次数多而拒绝执行。

## 4. 现金与积分

用户在同一个全局助手中明确选择：

| 通路 | 模型来源 | 结算 |
|---|---|---|
| 现金额度 | 用户选择现有平台模型目录中的模型 | 沿用实际服务方扣费 × 2 的现金规则 |
| 平台积分 | 管理员启用的平台模型配置；初始拟用硅基流动 Qwen3-8B | 使用平台积分规则，与现金账本分离 |

### 4.1 执行计费

二者共用会话、工具与执行记录。每次执行开始时固定资金通路、模型配置版本和费率版本；后续切换只影响新执行。一次执行内部所有实际模型调用都记录，包括纠错、分段继续及使用模型做上下文整理的调用，不能只计算最后一条正文或最后一次 API 响应。

现金发送沿用已经确认的规则：在实际开始调用模型前，余额大于零可开始，不以最高预留金额拦截；成功执行按实结算，允许结算后变为负数；余额小于等于零时不能开始下一次现金执行；真正失败或被停止且未交付成功结果的执行不扣本站现金额度。保留实际用量、费用和余额展示，用户界面不显示内部倍率或服务方关系。

一次需求澄清或保存草稿后正常返回的执行也属于成功交流，按该次实际调用计费；不能因为整张地图尚未发布就把此前所有成功轮次变成免费。已成功交付的结果在通知断线时仍是成功，不能被归入“失败不扣费”。

同账号现金执行继续串行，包括不同对话。后续执行等待前一执行结束后检查已确认余额；该保护不计算最高费用、不预扣估算金额。并发进入不同页面不能多次绕过“最后一笔正余额只开始一次”的规则。

### 4.2 真实费用与待核对

源码审计确认当前 DSH 用量协议只有 Token 数，缺少真实金额回执。现金路径迁入统一执行前，必须补齐每次模型调用的真实费用来源、币种、关联标识和聚合规则，并与现有结算结果对照。不能以参考单价或缓存未命中估算冒充真实扣费。

每次模型调用在发送前建立调用记录，保存所属执行、模型配置快照、请求关联标识；收到正文、用量或费用后分别保存。现金实际费用仅汇总已归属到本执行的真实回执，重复到达的回执不重复计入。费用覆盖尚不完整时，总金额保持未知，不把当前收到的一部分当作最终账单。

同一调用收到互相冲突的费用时保存原依据及冲突原因，进入待核对，不能选择最后一个值覆盖；按既有币种和金额精度规则处理，不借参考价格或浮点误差补出一笔费用。

执行进入业务终态后不再发起新的模型调用。已发送调用的集合固定，每个调用分别记录已完成、已确定终止或状态未知；状态未知的调用也需要核对，不能从账单里直接丢掉。已知调用全部有明确费用依据后，才能把汇总费用标为完整。

正文或地图完整、但真实费用尚缺失时，保存业务结果并显示“费用待核对”，执行不重新生成、不假装失败、也不声称已经扣费。结果可查看和继续学习；“生成成功”和“结算完成”在记录与界面中分别表达。

恢复只检查原调用的回执、已保存结果及结算记录；查询费用不能变成再次发送原生成请求。对接服务支持查询时按原请求关联标识核对；不支持查询或一直查不到时，持续保留待核对记录，并在管理员面板展示该执行、缺失调用、已知信息、最后查询时间和当前原因。进入后台检查，状态变化或新未决记录出现时提醒，避免重复无意义通知。

**未决费用不设置自动过期时间，不填零、不用参考价补算、不自动免收、不自动结案。** 管理员没有真实费用依据时也不能将它标为已结算。真实回执以后到达，再为原执行补结算一次；即使用户已经拿到结果，也不能另建执行收第二次费用。

已结束业务的费用核对不长期占用数据库连接、草稿写锁或模型执行席位。同账号的实际现金调用继续串行；历史待核对记录不构成额外的最高预留拦截，新执行按已确认余额判断。晚到费用补扣可能使余额为负；已经在正余额时接受并开始的执行不因此中途取消，后续新现金执行再按余额判断。

真实回执明确为零与金额未知分开记录。只有前者可以按实际零费用结算。模型配置启用现金通路前验证真实费用来源；缺少可验证费用能力的配置不能假称支持正式现金结算。

### 4.3 发布、结算与结果通知保持一致

模型调用和网络访问不放在数据库事务里。待发布草稿及逐次费用依据先持久保存；最后的短事务校验执行所有权、未被停止、草稿版本及幂等标识，并同时写入：

1. 正式地图或正式回复、来源执行及完成卡片的目标。
2. 本执行的结算记录。真实费用齐全且能按资金规则完成入账时同事务写流水及余额；费用不齐时写金额未知的待核对记录，费用明确但暂不能入账时保存真实金额及待入账原因。
3. 执行业务成功状态和待发送结果事件。

事务失败不能留下“地图已发布、执行却失败”的一半状态。提交响应不确定时，按执行和发布标识查询数据库；已提交则重放原结果，未确认提交状态前不得重建地图、重新发模型请求或再次扣费。事务提交后的消息读取或前端通知失败，只影响交付通知，不改业务成功状态。

待核对费用后续补结算时，用另一个短事务同时锁定原结算记录、写唯一消费流水、更新余额及结算状态。原执行的结算标识唯一；重复查询、回执、重启和并发补结算都返回原费用记录。费用落库失败保持待入账，可重试这个事务；不能把已成功结果降级为生成失败，也不能再次调用模型。

若首次包含扣费的提交失败，先核实整个事务有没有提交；明确未提交、且数据库仍可正常保存业务及待入账记录时，重试提交业务结果、已知真实费用及待入账状态。数据库整体不可用时，待发布版本及费用依据保持可恢复，不能声称正式地图已经保存，也不重发模型调用。

若有效建图版本已准备好，最后总结回复断流，可以用已保存地图信息生成确定性的完成卡片继续发布；这不需要再请求模型。若尚无有效版本，只保留草稿并记录执行失败。纯问答则需要完整可保存的正文才算成功。

用户点击停止与最后提交争用同一执行状态：停止先成功记录时禁止再发布或扣费；提交先成功时显示原完成结果，之后的停止不得把已完成执行变成免费失败。真实终态由保存记录决定，不能由前端收到哪个事件决定。

平台积分和旧的免费生成次数属于不同权益，不能继续共用含混的消费计数。积分新路径不依赖旧生成器的免费次数状态；历史摘要仍按历史记录的真实资金通路解释。积分定价沿用现有配置，本文不另行设定价格。

积分也按执行记录与唯一结算标识入账。积分用量或落库暂缺时保存待核对/待入账状态，不重复执行，不把未知用量视为零；沿用既有积分余额政策，不在本设计中擅自增加积分透支规则。结果已经完整、但积分余额不足以按现有规则入账时，记录结果成功及待入账，补足积分后只结算原执行，不能重新生成或使积分账本未经授权变为负数。

硅基流动 8B 是初始配置候选，其工具调用、思考输出、长任务完成度和账号可用性需要真实验证。模型能力影响任务成功率，统一执行不保证每个模型都能完成复杂建图任务。

## 5. 后台模型适配配置

当前已经存在管理员模型切换 API 和页面，复用它们扩展。当前实现只允许两个源码常量配置：硅基流动 Qwen3-8B、Qwen2.5-7B-Instruct；选择保存在运行内存中。现有切换机制会先启动新执行进程，再让后续请求使用它，可以作为扩展基础。

新配置包含显示名称、适配器类型、服务地址、模型标识、服务端密钥引用、上下文与最大输出能力、工具及流式支持、思考参数支持情况。只把真实的模型能力写在模型配置中，不给所有模型套用某个 8B 模型的统一上限。

管理员可以在后台新增或编辑适配器支持的配置，测试并启用积分默认模型。配置和当前选择持久保存，服务器重启后恢复；不必修改源码才能切换同一协议下的模型或服务地址。已有服务端密钥可通过受控引用选择，密钥原文不进入普通客户端和日志。

先支持已有协议及适配器。不同协议通过相应适配器接入，不承诺填写任意地址就能调用任意模型；不支持的参数由适配器明确处理，避免把供应商特有参数直接发给其他模型。

启用流程为：校验配置、建立运行环境、验证所需能力，再更新持久化的生效版本。失败保留旧配置正常服务。每次执行持有完整的不可变配置快照，包含地址、模型、密钥引用、能力和结算版本；密钥引用也绑定具体版本，不能通过修改同一个别名暗换旧执行的接入。切换过程不得混用新旧信息，运行中的执行继续使用原配置。旧快照保留到相关执行恢复、费用核对和结算不再需要它，不能在重启后用新的默认配置恢复旧执行。

平台积分默认模型与用户现金模型选择分开管理。修改积分模型不改变用户已经选定的现金模型。后台修改继续受管理员鉴权、写入保护和操作记录约束。

## 6. 恢复、诊断与上下文

### 6.1 断线、停止与继续

复用现有聊天、工具诊断及持久化渠道。执行归属、逐次调用、草稿版本和有序事件由服务端保存，模型运行所有者不依赖浏览器连接。事件带执行标识和递增序号，重连从上次序号继续，并能直接获取最终保存状态。

| 情况 | 明确行为 |
|---|---|
| 浏览器断线、刷新或切页面 | 仅断开结果订阅，后台执行继续；重连读取同一执行及事件，不重发生成请求 |
| 用户点击停止 | 明确发送停止命令；执行不再开始新模型调用或工具写入，取消可取消的在途调用；保留已提交草稿、调用与诊断；未交付成功结果的执行结束为已停止且不扣现金 |
| 停止后点击继续 | 创建新执行，读取同一草稿的最新版本和未完成目标，可以更换模型/资金通路；只核算新执行新增调用，不搬入旧失败或已停止执行的费用 |
| 运行中或恢复中的重复点击继续 | 附着到原执行；不能启动第二个草稿写入者或重新扣费 |
| 服务器重启或执行者失联 | 接管同一执行，先查已完成操作、模型调用状态、结果及结算；从已确认检查点恢复，不从头生成 |
| 地图或结算提交结果不确定 | 先按幂等标识查记录；已提交重放原结果，状态仍未知保持恢复/待核对，不能直接重做 |
| 业务已完成、结果通知丢失 | 只重送原结果和费用状态，不调用模型、不重建地图、不新增收费 |

停止请求、恢复请求也以操作标识去重。未完整的正文可保留为诊断和草稿，不混成已完成回复；已经成功提交的地图、回复和费用不能因后到停止请求被撤销。

### 6.2 所有权与不确定调用

一个地图草稿同一时刻只有一个执行写入者；同一对话也沿用执行归属保护。写入持久化的所有权代次和草稿版本，接管后旧执行者的晚到写入必须被拒绝。所有权续租用于识别失联和接管，不限制任务总时长；不能让过期旧进程继续发布或结算。

工具动作在执行前记录操作标识，执行后持久保存结果；恢复先查已完成动作。版本冲突向 Agent 返回最新状态并让其纠正，不能无条件覆盖。现金账号串行保护贯穿实际运行与收尾，不只存在于某个浏览器或单个会话中；重启通过持久状态恢复这一保护。

执行归属与串行保护依靠可接管的持久状态和短事务，不靠整个模型运行期间占用数据库长事务。相同操作标识携带不同参数时返回冲突，不能悄悄更改原操作或沿用错误结果。

模型请求发送前保存调用标识和输入摘要，发送后区分已完成、明确未执行及执行状态未知。服务方支持幂等或请求查询时按原标识使用。若连接中断后无法证明原调用有没有执行，保留为待核对，不自动再发同一请求；没有幂等/查询能力时不承诺外部调用绝对只执行一次。

已经停止或失败执行的晚到回执只补全审计事实，不把它重新归类为成功收费。已经成功但费用待核对的执行，晚到回执只补结算。恢复过程不因为缺正文或费用就创建新执行来掩盖旧状态。

### 6.3 诊断与目标模型上下文

工具校验及执行失败记录工具名、执行阶段、具体原因、字段或版本信息，并保留去除密钥等敏感信息后的原始错误。模型获得其当前任务范围内可纠正的错误结果，普通工具失败不直接终止整个会话。模型服务不可连接等无法继续执行的情况保存诊断和草稿，界面显示简短安全提示及请求编号。

读取个人地图采用分页目录、概览、节点搜索、单节点和指定关系等现有颗粒化工具。全局助手从明确任务定位目标，学习区继续限定所属图；不把所有地图、所有笔记或其他会话全文默认注入模型。

每次执行和执行中的后续模型调用，都按目标模型真实窗口准备上下文。大窗口切小窗口时，保留当前用户需求及已确认约束、草稿最新索引与版本、未完成事项、待确认操作以及近期完整的模型工具请求与结果。旧交流整理为可追溯摘要，较长资料和工具结果保留在存储中按需读取，不简单丢弃最近一轮，也不截断工具往返的一半。

工具往返保留完整的调用与结果对应关系；结果过长时采用可读取的结果引用及摘要，让目标模型继续按需取原文，不把一个巨大的工具结果强塞入小窗口，也不只保留调用而丢失结果。

换模型同时转换消息与思考/工具协议，不把前一个模型特有字段照搬。旧上下文仍能按记录检索；新模型不会因为窗口小而拿到一段失去当前需求的空历史。当前用户需求过长时保留原文引用并分段读取，明确记录何处采用摘要；摘要产生模型费用时仍归本次执行。

### 6.4 成功与质量分开验收

技术成功需要正式结果保存、归属正确、结构有效、过程与结算状态可恢复。教学质量另行审查：主题与用户目标一致、阶段符合学习者背景、关键能力覆盖充分、先修关系合理、专业事实正确、连续修改不悄悄遗失旧要求。

真实验收分别覆盖：简单入门主题、复杂专业主题、信息不完整的需求、同一草稿多轮修改。对照现金模型与积分候选模型，记录技术成功和教学质量各自的结果，不把“合法 JSON、已保存”当作内容质量合格。不达标的积分模型可以由管理员切换，不通过新增执行次数上限或重新加固定多阶段流水线掩盖问题。

## 7. 链路迁移与实施验证

### 7.1 保留与退役范围

| 现有部分 | 处理 |
|---|---|
| 全局管理聊天、学习聊天、独立酒馆页面和角色/历史归属 | 界面保留，共用执行服务；工具及资料权限按场景提供 |
| 现金平台及自填 Key 的 Rust 独立工具循环 | 真实费用与模型协议能力验收后迁入 DSH；移除重复的 Agent 循环，保留必要的模型适配和费用解析能力 |
| 积分 DSH、无工具酒馆的单步执行通路 | 合并到统一执行协议，取消单步/16 步等人为限制；无工具由能力集合表达，不另造循环 |
| 独立技能树生成表单及规划/研究/组树流水线 | 新草稿工具验收后停止接收新请求，退役重复执行逻辑；在途旧执行按原归属处理，保留历史读取 |
| 地图存储、结构校验、学习区、角色、画布及已确认修改能力 | 作为统一执行调用的领域能力保留，不重新实现一套数据库 |
| 现金/积分账本、历史费用和外部模型接入 | 保留资金边界及历史事实，补齐执行与逐次调用关联，不能靠删记录完成迁移 |

迁移期间按执行创建时记录的版本明确分流，不能在恢复中途换执行器。新链路验收完成后不再让旧入口开启旧循环；清理无调用代码时复核调用关系，避免新增页面后留下三套活跃执行机制。

### 7.2 实施顺序

业务逻辑每步先写能复现缺口的测试，确认失败后实现，再跑绿和整理。纯样式与文档无需业务 TDD。

| 步骤 | 影响范围 | 验证 |
|---|---|---|
| 1. 执行、草稿、费用和结果状态 | 执行存储、草稿操作、所有权、结算及结果事件协议 | 三轮需求各自结算；一次恢复只有一个执行；同草稿单写者；事务和回执异常注入 |
| 2. 统一执行及取消硬上限 | Rust/DSH/通信协议、工具分发、流式订阅和恢复服务 | 超过原 8 次工具/16 步仍继续；长时执行不因原期限失败；断线继续、明确停止、重启恢复及状态未知不盲重发 |
| 3. 模型配置与窗口适配 | 平台配置存储、管理员接口和页面、模型与上下文适配 | 重启恢复配置；切换失败保留旧服务；旧执行固定快照；大窗口到小窗口保留需求、草稿和完整工具往返 |
| 4. 默认全局助手与真实建图 | 路由导航、地图草稿工具、批量操作、正式发布、费用聚合、完成卡片及学习区跳转 | 图/消息/费用记录/成功状态一致；待核对不填零、不重生成；重复回执与重试唯一结算；旧学习界面和手机入口回归 |
| 5. 内容质量、资金回归与旧链路退役 | 多场景实测、新旧入口切换及无调用代码清理 | 四类需求分别评估技术成功与教学质量；真实费用、Token 和耗时对照；全局/学习/酒馆/自填 Key 回归；完整测试、类型、lint、构建及 diff 自审 |

真实建图和现金上线以执行、恢复与结算规则先通过故障测试为前提。新增页面或模型配置可以单独预览，但不能将其当作整条新执行链路已完成。移除旧生成执行路径必须在新路径实际通过验收后进行。

### 7.3 必须覆盖的失败场景

- 三轮补充一个草稿，各轮费用独立；停止后继续可换模型，重连恢复不换模型、不再扣已入账费用。
- 地图待发布版本已保存后总结断流；正式发布后通知断线；提交响应丢失或提交后读取失败。均先查保存状态，不重复建图或假报生成失败。
- 真实费用回执缺失、只收到部分费用、晚到、重复或冲突；保存结果及待核对提醒，不估算填零，费用齐全后仅补扣一次。
- 数据库在正式提交前失败、提交响应未知、结算后读取失败、已成功结果的后续补扣失败；检查地图、结果、结算记录和余额的一致性。
- 用户停止与最后提交竞争，服务器在工具写入前后重启，两个执行者尝试写同一草稿，旧所有者晚到写入；检查终态、版本和唯一产物。
- 单账号两个现金请求从仅剩正余额开始排队；前一个结算为负后拒绝下一个新执行；待核对费用晚到时不取消已开始执行。
- 连续工具纠错越过旧次数和时长边界；大输入及长历史换到小窗口；工具结果分段读取仍能继续任务。
- 简单、复杂、模糊、多轮修改四类教学需求；现金和积分各自真实建图，分开记录合法性与教学质量，列明缺失内容和错误关系。

本轮形成书面设计，不发起新的收费请求或生产数据变更。真实验收逐项记录请求、模型配置版本、Token、费用、保存的地图和结果页面；发布按具体通过验收的版本进行。
