# 知识聊天界面优化设计

## 目标

解决当前知识聊天面板在桌面端过窄、长回答换行异常，以及 Agent 返回的基础 Markdown 语法无法正常显示的问题。优化后，用户可以在不离开技能树的情况下获得更宽、更可控的聊天区域，同时保留手机端的全屏聊天体验。

## 范围

本轮包含：

- 桌面端聊天面板改为可拖拽调整宽度，默认宽度约为 460px，最小 360px，最大 720px。
- 聊天面板左侧增加可识别、可操作的垂直拖拽分隔条；面板宽度变化时，中间技能树区域自动让出空间。
- 移动端继续使用全屏聊天布局，不显示桌面端分隔条，也不改变现有返回/关闭行为。
- 对 Agent 消息增加安全的轻量 Markdown 渲染：标题、粗体、斜体、行内代码、围栏代码块、无序/有序列表、引用和链接。
- 不使用 `dangerouslySetInnerHTML`；原始 HTML 作为文本处理，避免 Agent 输出被当作页面标记执行。

本轮不包含：

- 流式输出和打字机效果。
- Agent 系统提示词、技能树边界和“列出全部技能”问题。
- 积分计费策略调整。
- 引入完整 Markdown/GFM 解析依赖或支持复杂表格、脚注等语法。

## 交互方案

### 桌面端宽度调整

`App` 持有当前聊天面板宽度，初始值为 460px。聊天打开时，在聊天面板左边渲染一个垂直分隔条：

- 指针按下后进入拖拽状态。
- 指针向左移动，聊天面板变宽；向右移动，聊天面板变窄。
- 宽度始终限制在 360px～720px 范围内。
- 分隔条只在桌面布局显示，移动端隐藏。
- 分隔条使用 `role="separator"`、垂直方向和当前值等 ARIA 信息，并支持键盘左右方向键微调，保证不用鼠标也能调整。

面板采用内联宽度而不是固定 Tailwind 宽度类，关闭聊天时不保留可见的分隔条；重新打开时保留用户刚才调整的宽度。

### 消息内容

用户消息继续按纯文本显示，保留换行；Agent 消息通过 React 元素渲染基础 Markdown。代码块使用横向可滚动容器，普通段落和列表允许自然换行，避免窄面板把整段回答压成异常细长的气泡。Emoji 继续作为普通 Unicode 文本显示。

链接只允许常规 `http`/`https` URL，并在新标签页打开；不接受 `javascript:` 等危险协议。

## 组件和数据流

```text
App
 ├─ chatWidth state
 └─ ResizableChatPane
     ├─ ChatResizeHandle
     └─ KnowledgeChatPanel
         └─ AssistantMarkdown
```

- `ResizableChatPane` 只负责桌面端尺寸、拖拽和可访问性，不参与聊天请求。
- `KnowledgeChatPanel` 继续负责会话状态、发送请求、余额和错误状态。
- `AssistantMarkdown` 只负责把已收到的 Agent 文本转换为安全的 React 节点，不修改消息数据。

## 验证方式

- Markdown 渲染测试：粗体、代码、代码块、列表、链接和原始 HTML 不执行。
- 聊天面板测试：Agent 消息使用 Markdown 节点显示，用户消息仍保留换行。
- 可拖拽面板测试：默认宽度、拖拽方向、最小/最大边界、键盘调整和关闭时分隔条隐藏。
- 运行前端完整测试、TypeScript 检查和生产构建。
- 启动本地页面进行桌面截图检查，并确认移动端布局仍为全屏聊天。

## 验收标准

1. 桌面端聊天面板打开后明显宽于当前 320px，长回答不再被挤成窄列。
2. 用户可以拖动左侧分隔条改变宽度，技能树区域随之缩放。
3. `**粗体**`、代码块和列表等常见 Agent 输出能正确呈现，原始 HTML 不会改变页面结构。
4. 手机端不出现拖拽条，聊天仍占满可用页面宽度。
5. 现有聊天发送、余额扣除、关闭后重新打开保留会话等行为不回归。
