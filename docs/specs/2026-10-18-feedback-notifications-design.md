# 消息中心与反馈回复

已确认范围：2026-10-18 用户要求本轮只做反馈及其通知入口；收款监控、安卓、邮件和资金流程不在本轮内。

## 行为

- 桌面头像上方显示消息铃铛；手机复用页面顶栏放铃铛，不再增加一行。未读公告和反馈回复出现红点。
- 消息中心分全部、公告、反馈回复，分页读取。打开列表不自动清除未读；查看某条内容或手动标记后更新服务器已读状态。
- 反馈内分写反馈、已反馈；保留原文和时间，显示等待回复 / 已回复。用户可以查看平台追加的回复。
- 管理员可筛选待回复反馈、查看和回复。回复、通知、审计同事务保存；请求响应丢失重试不会重复生成回复。
- 旧公告、已读记录和反馈保留，旧接口兼容；普通公告不再在进入网站时自动弹窗。
- 界面使用现有米色、暗色样式，兼容 320–1440px、键盘焦点和触屏。

## 接口与数据

新增 /api/me/feedback 的提交、列表、详情，/api/me/notifications 的列表、未读数及单条标记接口；管理员新增反馈 threads 列表、详情和 replies 提交。旧 /api/feedback、/api/admin/feedback、公告接口维持合同。

反馈提交和管理员回复携带 requestId，重复相同内容返回原记录，同 ID 换内容返回冲突。用户查询、详情和已读必须绑定账号；回复必须校验管理员及 CSRF。

回复追加存储；个人消息保存来源和已读时间。公告复用 announcements / announcement_reads，通过统一查询展示，不复制全量公告到每个账号。

列表每页 20 条，稳定游标分页。未读数在可见页面约 30 秒刷新，切回页面刷新；数据缓存按账号隔离。只标记本次实际展示的回复 ID，不能清掉之后新来的回复。

## 步骤与验证

1. 后端 HTTP 行为测试跑红后实现：提交、用户回看与权限隔离；验证旧提交仍可用。
2. 后端回复与消息测试跑红后实现：管理员权限、同事务、重复请求、已读及并发到来的新回复、分页。
3. 前端组件行为测试跑红后实现：反馈保留草稿、显示等待状态、打开回复、红点与管理员回复；不自动清已读。
4. 完整测试、类型检查、格式与构建；单独记录已有失败，不把基线问题记成本轮通过。
5. 浏览器实际点击并在手机 / 桌面、米色 / 暗色截图验收，再提交代码和交接。本轮不自动部署。
