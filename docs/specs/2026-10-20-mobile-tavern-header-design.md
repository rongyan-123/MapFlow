# 手机酒馆顶栏整理

日期：2026-10-20。状态：静态设计已完成，等待用户确认；尚未修改产品组件、测试或线上应用。本方案继续使用当前 `codex/mobile-canvas-access-20261020` 工作区，不新建工作区。

## 当前问题与修改范围

截图中的手机酒馆顶栏同时放置功能菜单、智能体与会话、消息、配置、教学画布、更多，共六个入口。`PageHeader` 提供菜单与消息，`ConversationWorkspace` 追加配置、画布与更多；手机样式把间距压到 0～2px。智能体按钮又带完整边框和阴影，名称与各按钮争抢注意力。

本轮整理小于 768px 的独立酒馆顶栏和对应“聊天操作”面板。当前智能体和会话绑定、模型、计费、角色库及历史数据均沿用已有实现。学习区的画布快捷入口及桌面操作区不按酒馆的使用频率收拢。768px、1024px 及以上分别验证既有布局未被手机样式误覆盖。

## 两种布局

| 方案 | 顶部安排 | 取舍 |
| --- | --- | --- |
| A，推荐 | 单行保留菜单、当前智能体、消息、更多；配置与画布放入带文字的操作面板 | 顶部保持紧凑，智能体名称有更多空间；配置和画布多一次点击 |
| B | 第一行显示菜单、当前智能体和消息；第二行显示配置、画布与更多 | 工具直接可见，顶部占用约两行高度，聊天首屏缩小 |

推荐 A。独立酒馆以切换智能体和聊天为主，画布是可选工具。消息及未读红点仍直接可见，当前智能体按钮继续打开现有会话抽屉。

## 推荐方案的样式与行为

- 顶栏从 52px 调整到约 68px；左右留白 12px，主要入口之间留 8px。图标仍用现有 SVG，按钮点击区域至少 44×44 CSS px。这是本项目的触控目标，不把该数值当作所有网页的统一合规门槛。
- 当前智能体是视觉重点：淡色图标底、小字“独立酒馆”、加重的当前角色名和下拉箭头。去掉原按钮的整块重边框与阴影。超长名称单行省略，打开抽屉后可查看完整名称。没有会话时仍提供智能体选择入口。
- 菜单图标负责工作台导航；铃铛负责平台消息，继续显示已有未读红点；“更多”以轻边框方形按钮呈现，避免与智能体名称争抢注意力。
- 点击“更多”复用现有 Dialog 和回调，面板以文字和图标展示“新建会话”“会话历史”“教学画布”“聊天配置”；画布入口说明当前展开状态。原有额外操作如存在，也须保留。米色、暗色均使用现有主题变量。
- 更多面板内执行操作后先关闭该面板，再打开原配置、抽屉或切换画布；取消或 Esc 返回“更多”按钮，不能清空输入草稿、切换角色或触发模型请求。
- 继续使用已有模型选择入口。正文、聊天输入框和其他页面不参与此次视觉重排。

## 实施步骤与验证

1. 在共享聊天组件和酒馆标题入口中增加局部样式边界，完成四入口顶栏。用真实组件检查智能体、通知及菜单仍调用原操作；浏览器检查 320、390、586px 和超长角色名，没有重叠与横向溢出。
2. 在更多面板接入现有配置操作并整理文字入口。交互逻辑先写失败测试，再实现；通过真实 `ConversationWorkspace` 与酒馆页面入口验证每个回调只执行一次、面板关闭、草稿保留、焦点返回及画布可再次收起。
3. 检查米色与暗色、横屏、768/1024/1440px、未读提醒、没有会话和有消息的状态；运行前端完整测试、类型检查与构建，自审差异并更新验收记录。
4. 保持本地预览供用户检查。生产部署继续等待明确批准，并遵守活动聊天期间不部署的要求。
