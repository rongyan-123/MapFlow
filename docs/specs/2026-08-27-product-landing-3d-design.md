# MapFlow 产品介绍页与 3D 技能树展示设计

## 目标

为 MapFlow 增加一个面向首次访问者的产品介绍页。页面先解释产品价值和使用方式，再把用户带入现有 `/console` 控制台。产品页中的核心技能树展示必须是真正可交互的 3D 场景：用户可以旋转、拖拽、缩放并选中节点，直观看到节点层级和依赖关系。

本阶段只改前端，不改后端接口、数据库、计费、登录协议或控制台业务逻辑；不读取真实用户树，不把隐私数据放入宣传页。

## 参考拆解

- OnScrollPathAnimations 的可复用思想是“滚动就是叙事进度”：用 SVG 路径、分隔线和章节进入视口来表达从意图到结果的过程。MapFlow 只借鉴这种节奏和路径变形，不复制素材或页面内容。
- Specia1ne 的重点是信息架构和视觉节制：Signal、Selected Work、Practice/System、About、Contact 形成连续叙事，编号、留白和重复的视觉线索让页面像一个完整产品系统，而不是一组孤立卡片。
- codrops-batchedmesh 的重点是 Three.js/WebGPU 场景、轨道相机和后处理。MapFlow 的首版采用 React 18 兼容的 Three.js/R3F WebGL 路线，并保留无 WebGL 降级；WebGPU/BatchedMesh 作为未来大量节点场景的性能方向，不作为当前页面的硬依赖。
- 3d-weather-codrops 的重点是 R3F 场景组织、粒子、光照和氛围层。MapFlow 借鉴层次化光照与环境氛围，不引入天气语义，也不复制其外部天气服务。

## 页面结构

### 入口与路由

- `/`：产品介绍页。首次访问或显式打开产品介绍页时展示。
- `/console`：现有控制台，保留当前登录、个人树库、公共树库、生成、聊天和管理员入口。
- 已登录且已经进入过控制台的用户，继续按本地入口偏好直接进入 `/console`，不强迫每次重新看宣传页。
- 产品页所有“开始使用”“进入控制台”按钮复用现有 `onEnterConsole`；未登录用户的登录按钮复用现有身份弹窗，不在 Landing 内复制认证逻辑。

### 已确认的首页语气

首页不使用“主 CTA”“查看方法锚点”或其他内部产品术语，直接说用户正在经历的痛点：不想再被无聊网课拖着走，也不想在项目里一次面对所有问题。MapFlow 的承诺是把复杂技术拆成可以执行的小节点，用户想学哪里就从哪里开始，卡在哪里就问哪里。

首版核心文案：

> 不想再看无聊的网课，从你真正想学的地方开始。

> MapFlow 把一门复杂技术拆成一棵可以探索、可以执行的技能树。每个节点都是一个明确的小目标，沿着依赖关系学习，今天就能开始，学到哪里算到哪里。

结尾引导使用“告诉 MapFlow，你想学什么”，把用户直接带入控制台，而不是要求用户先理解产品术语。

### 章节

1. **首屏**：直接说出“受够了无聊网课”的痛点，解释“想学哪里就从哪里开始”，提供进入控制台按钮。
2. **Skill tree / 3D 正式展示**：3D 技能树舞台。节点按层级分布，边表示依赖，颜色区分能力维度；支持轨道旋转、平移、缩放、悬停和选中。旁边显示当前节点的简短解释，提醒用户“这是一棵可以探索的技能树”。
3. **Workflow / 工作方式**：用滚动章节和路径式分隔线讲清楚“说出目标 → 拆成节点 → 沿前置关系推进 → 留下完成证据”。
4. **Practice / 产品能力**：围绕真实功能展示结构化路径、节点证据、树内 AI 教练、导出成果，不使用泛化的营销卡片堆叠。
5. **Start / 最终 CTA**：说明登录后可以保存自己的学习路径，提供进入控制台按钮。

## 3D 场景设计

### 技术边界

- 使用 React 18 兼容版本的 `three`、`@react-three/fiber` 和 `@react-three/drei`；不直接引入 WebGPU 作为唯一渲染路径。
- 3D 场景作为独立懒加载的 `SkillTree3D` 组件，内部只使用脱敏的演示节点和连线，不读取真实用户树。
- 3D 区域加载期间显示稳定的 DOM 占位图，浏览器不支持 WebGL 时继续显示可读的 2D 结构。
- 场景不请求 API，不访问登录态，不把真实树 ID、账号信息或内部字段暴露到产品页。

### 交互契约

- 鼠标左键拖拽或触摸拖动：旋转视角。
- 鼠标右键/中键或双指手势：平移；滚轮/双指缩放：调整距离。
- 节点悬停：显示可操作光标和节点高亮，保留清晰的标题与简短说明。
- 节点点击：更新旁侧的简短节点说明；不能跳转到真实个人数据。
- 提供“重置视角”按钮；提供文本化的节点摘要，保证键盘和读屏用户仍能理解内容。
- 尊重 `prefers-reduced-motion`：减少自动漂浮和入场动画，但不关闭用户主动旋转。

### 视觉语言

- 深石墨背景作为 3D 舞台，使用青色/蓝色表示路径和进行中节点，琥珀色表示证据或 CTA，低饱和灰色表示待学习节点。
- 节点使用半透明体积感材质、边缘高光和轻量环境光；连接线保持清楚，不能被光效吞掉。
- 控制面板使用简短、明确的操作提示，避免把 WebGL 控制参数暴露给用户。

## 叙事区与响应式

- 叙事区使用语义化 section、原生滚动和 CSS 路径式分隔线；简单渐入使用 CSS，复杂布局变化再引入现有项目认可的动画方案。
- 桌面端展示完整 3D 舞台和旁侧节点说明；平板端缩小舞台并把说明移到下方；手机端默认展示可拖拽的 3D 舞台和紧凑文本摘要，失败时自动显示 2D 降级图。
- 所有按钮保持可见焦点、足够点击区域和清晰对比度；不依赖颜色作为唯一状态表达。

## 测试与验收

### 自动测试

按垂直切片执行红-绿-重构：

1. Landing 公开结构测试：首屏文案、3D 展示区、工作方式、能力区、最终 CTA 都能被用户可见文本或稳定测试标识找到。
2. CTA 行为测试：点击进入控制台调用既有入口回调，不改变登录逻辑。
3. 3D 组件契约测试：场景容器可渲染，演示节点摘要存在，重置视角和选中节点的公开行为可用；测试不绑定 Three.js 私有对象。
4. 降级测试：WebGL 不可用或场景加载失败时仍显示可读的 2D 技能树摘要。
5. 运行前端全量 Vitest、typecheck 和 production build。

### Browser Harness 验收

- 打开产品页，确认首次页面不是直接进入地图控制台。
- 实际拖拽 3D 舞台，检查视角发生变化；滚轮缩放后节点仍清晰可见。
- 点击一个节点，确认旁侧说明切换；点击重置视角，确认回到初始视角。
- 滚动经过 SVG 叙事章节，确认章节动画和锚点不遮挡内容。
- 点击 CTA，确认进入现有 `/console`；在已登录状态下刷新，确认入口偏好仍按既有规则工作。
- 检查桌面、窄视口和手机视口；检查 WebGL 降级、键盘焦点和 `prefers-reduced-motion`。

## 交付边界

- 本分支只包含产品介绍页、3D 展示组件、必要的前端依赖/测试和设计文档。
- 不修改后端、不部署、不更新生产环境配置。
- 提交时只暂存本功能相关文件，保留公告、交接文档和其他未提交改动。
- 用户验收通过后，再讨论如何把这组提交合并到主仓库 `main`；在此之前不推送、不部署。
