# MapFlow 首页、学习工作台与探索入口重设计

## 授权与目标

用户已批准上一轮首页、树介绍、具体问题入口方向，并明确授权自由设计、重构目前混杂的界面。主任务负责设计与审查，实现交由用户指定的 gpt-5.6-luna / max 独立任务。本规格是已授权方向的具体化，不需要再次询问同一批准。

本轮完成可运行、可审查的前端改版，不修改服务端计费、赠送、认证、数据库，不部署。测试与构建必须完成。

已知数据：169 个非管理员账号中 135 个有树库，其中 84 个没有完成或聊天记录。它们可能读过内容，不能断言没学习。当前入口把生产级完整体系、节点评估、工具配置同时摆在用户面前。目标是帮助首次用户选择一个具体问题并开始探索，而非强制做题、全树点亮或配置模型。

## 设计决策

考虑过仅换 Hero、添加论坛/万能 AI、重构入口三条路线。选择入口重构：前者无法解决已有树后的断点，论坛与空聊天框会增加未验证功能。

### 一、产品首页 `/`

- 独立的简洁展示页面，不是控制台外加一段营销文案。
- 视觉采用柔和浅底（米白/浅雾灰）、深色字、少量青绿或蓝色强调、宽留白与明确字号层级。探索地图可以保留适宜长时阅读的暗色画布；交接区域有一致品牌和按钮语言。尊重已有主题系统，避免全局无差别覆盖。
- 第一屏核心文案：`把你想懂的东西，展开成一张地图。` 配简短副句 `选一个好奇的问题，看看自己能走到哪里。` 主按钮 `试着探索一下`，次入口登录/继续学习根据状态展示。
- 配图是清晰的 MapFlow 节点与依赖示意，最好复用现有真实官方树的裁剪/轻量 SVG/HTML 节点呈现。演示需标记为示意，不伪造用户真实进度。不要为装饰加载重型 3D，不复用原先抽象漂浮场景作为首要价值表达。
- 后续至多两个简短图文章节：`选一个好奇的问题，往下追。`；`你弄懂的，都会留下痕迹。` 每段一个清楚的视觉焦点。
- 参考 https://codepen.io/gridmorphic/pen/WbQPRwv 的分段留白、图文对应、滚动揭示。参考其思想即可，不需新加 GSAP/Lenis，不照搬远程图片。移动端自然滚动，不强制滚轮翻页、不阻止滚动或要求看完故事。prefers-reduced-motion 下关闭位移/固定滚动装饰。
- 首页首屏必须可直接进入工作台。MCP、反馈、公告和账户设置放次级入口，不与主 CTA 竞争，现有功能入口不得消失。

### 二、学习工作台 `/console`

- 首页与工作台的容器、导航、职责分离；工作台初始不渲染默认全幅树图或节点详情。
- 紧凑顶栏：MapFlow、探索/我的学习、账户入口；模型/签到/反馈/主题/MCP 等工具放账户/更多菜单或已有 drawer；移动端保留触控可达入口。不再顶部堆满按钮与状态。
- 主体有一条简短提示，例如 `今天想弄懂什么？`，已登录有树时优先提供 `继续探索`；展示真实已保存的节点进度，不用未经实现的理解深度或上次节点冒充真实数据。
- 官方树呈现为有介绍的方向卡，短标题、适合人群、一个具体问题、进入简介的明确动作。两张卡可以占据足够留白的完整内容区，不添加假内容、论坛、占位统计或未实现按钮来填空间。
- 可针对已知官方 Python/NestJS 树增加前端介绍元数据，必须用稳定标识/确定数据匹配并有通用 fallback，不能将所有自定义树误认为官方树。不得凭任意标题子串就强塞不相干学习问题。
- 公共树卡点击打开简短简介（独立视图或清楚的详情区），而非直接自动进入地图。显示：适合谁、能探索什么、必要的已有基础、一个推荐起点。避免完成时间/效果的无依据承诺。
- 简介主按钮 `开始探索`；次按钮 `先看地图`，允许自由浏览。匿名可查看介绍和地图。需要保存和聊天时走现有认证；注册/登录后保留用户选择与意图，不能丢回默认树。不自动发送付费消息或自动标记完成。
- 现有生成器保留为次级 `创建自己的地图`，保留免费/积分/BYOK原语，不改变账务。不把模型配置变成默认开始步骤。
- 已有个人树直接 `继续探索`，不强迫重复看介绍。只有两张卡也不堆教学文字填空。空个人库有清楚的选择方向入口。

### 三、树内探索

- 专注区域：返回工作台、当前树标题、地图/节点/聊天；减少头部及侧栏重复。桌面合理利用画布和右侧上下文，移动端单个主区域与明确返回路径。
- 节点详情以“你现在可以探索的问题/简短介绍”为先，目标深度、完整学习目标、通过标准、依赖等用原生 details 或清楚可访问折叠区逐步披露。不要损失已有信息。
- 给聊天提供 2–3 个可编辑的起始问题（例如解释当前节点、具体例子、与前置关系如何连接），依赖真实选中节点/树上下文。点击填入输入框并进入聊天，用户明确点击发送才触发模型与扣费。
- 从树简介推荐问题进入时，可以将问题传到聊天草稿；如需要个人树，使用现有加入接口，确认账号后再执行。避免重复加树、错树、跨账号草稿残留以及登录后丢意图。普通 `先看地图` 不创建个人数据。
- 知识聊天空白页以具体可做的事情开头，移除“只读知识助手”“我会读取xxx”等技术边界作为主要价值文案。后台权限完全不变。
- 自然问答也是学习；不声称聊天自动证明掌握。保留手动完成，但不把用户逼入通关考试。

## 实施步骤和验证

1. 阅读现有 App/landing/tree/identity/chat 及测试，运行基线测试，确认当前行为。验证：记录测试数和已存在问题。
2. 分离首页、工作台、简介、地图的视图状态与组件。新行为先写测试并确认红，再实现。验证：初始工作台无强制地图；简介与地图动作区分；返回路径正确。
3. 完成首页与工作台样式/短文案。纯样式不要求机械镜像测试。验证：375/390/768/1440 尺寸、无横向溢出、主动作可达、键盘与 reduced-motion。
4. 接通推荐问题到聊天草稿、登录后的意图恢复、个人树继续探索。验证：先红后绿的行为测试；无自动发送；不跨账号；不破坏已有生成/导出/完成/管理入口。
5. 审查与收尾。验证：完整 npm test、npm run typecheck、npm run build，git diff 自审。不能靠删除旧测试逃避回归：旧语义确实被替换时重写相应测试并解释。

## 验收与交付

- 首页、工作台、树内探索三者职责可区分。
- 用户可以从简短方向介绍进入一个具体问题，也能自由浏览地图。
- 不让匿名预览强制注册，不自动发送任何聊天请求。
- 明确描述浏览器验证是否执行。用户禁止 Windows 屏幕操控及移动现有窗口，仅允许 browser-harness。上一轮没有浏览器连接，后台隔离 Chrome 启动曾被自动审查 blocked by policy；不得绕过该拒绝。若仍无可用连接，完成其他验证并明确缺少视觉验收，不能声称截图通过。
- 产品代码实现和测试由 Luna 任务执行，主任务负责阅读 diff 和指导改进。本轮不 push、不部署、不改收费。保留已有未提交 .gitignore 与理论 ZIP。
- 不增加 TODO/虚假按钮/虚构用户统计；不用控制台术语描述用户价值。
