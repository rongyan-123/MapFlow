# 酒馆与学习聊天的共享核心整理

## 已确认的目标与范围

用户已确认上一轮提出的方向：统一会话核心、集中场景差异、让同一组行为测试同时验证酒馆和学习聊天。本轮仅整理前端聊天模块，保持现有路由、请求契约、外观和数据隔离；全局客服保持现有独立入口，后端、计费和数据库不变。

本轮因管理员回执修复暂停后，从最新 main `32bc6ec` 恢复，已包含已部署的学习区角色库与管理员回执修复。复用原有 worktree 和 `codex/chat-scene-core-20261016` 分支，合入主线后恢复已独立校验的测试；原具名 stash、分支和全部会话路径保留。

## 问题与选择

两个页面已经共用 SceneWorkspace。问题集中在各处自行解释场景、操作层直接依赖完整查询 hook 与查询缓存、页面同时维护角色库流程和五个配置页。

选择保留现有共享执行机制，在真实差异处整理模块职责。继续复制两套页面会扩大行为分叉；一次性重写执行、消息和缓存会放大风险。本轮不采用这两种方式。

## 模块职责与约束

1. 会话场景模块集中处理归属、缓存/选择命名空间、首次打开、创建端点与创建重试。学习区按账号和学习区隔离；酒馆按账号隔离；旧缓存键和请求 ID 保持兼容。主动清空后不自动创建；待确认的创建不能切换到另一角色重放；终止性错误清除待重试请求。
2. 历史模块继续负责查询和缓存一致性，向操作层提供明确的会话状态与领域操作，操作层不接收完整查询 hook，也不直接写角色缓存。
3. 页面继续编排历史、执行和布局。角色库的导入、创建、编辑、删除由独立的角色库流程管理；五个配置页由独立的配置模块渲染。消息、输入、发送/恢复、画布持久化继续使用已有实现。
4. 相同角色选择规则用于两个场景：完整私人角色库可见，恢复该角色最近选择的本场景会话，无会话时创建独立记录；角色间不复制历史、身份、词表和草稿。全局客服不获得私人角色切换能力。
5. 学习区保留地图与节点上下文、默认打开画布和允许 AI 绘图；酒馆保留手动打开画布。配置入口、手机抽屉和角色库关闭后的行为保持一致。

## 实施步骤与验证

1. 先建立以 TavernPage / LearningPage 真实入口为测试面的共同契约，网络只在 HTTP 边界替身；验证完整角色库、独立记录、草稿、首次创建、手机选择及场景隔离。现有行为的特征测试允许先绿，为纯重构提供基线。
2. 新场景模块先写公开接口测试并跑红，逐项实现归属/命名空间、端点和重试，逐项跑绿，再替换历史与操作层中的重复判断。新增业务逻辑遵守红绿循环。
3. 在已有和共同契约测试保护下缩小操作层依赖，拆出角色库流程和配置渲染；每次移动后运行针对性回归，避免边拆边改变业务规则。
4. 跑完整测试套件、类型检查与构建，审查 diff。用真实本地接口在桌面和手机检查角色库、切换、配置、画布和抽屉，并截图；保留原有聊天与地图，不发起付费生成。
5. 保存验证记录并提交。部署属于单独步骤，本轮不自动发布。

## 验收标准

两个真实入口执行同一份关键行为断言；操作层不再依赖 useConversationHistory 的返回类型或直接访问其 QueryClient 缓存；场景相关的创建/归属规则有单一来源；角色库流程和配置内容不再内嵌在页面编排中。所有既有回归通过，320px 与桌面无新增溢出、重复弹窗或数据串用。
