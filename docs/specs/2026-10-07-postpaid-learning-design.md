# 价格、充值引导、学习布局与发送后结算

用户已确认原前三项，并将第四项明确为：本站余额大于零即允许发送，不估算或预留费用；成功后依据完整上游账单结算，可以扣成负数。余额小于等于零时禁止新平台生成并引导充值。自填 Key 不使用本站现金。

## 实施与验证

1. 发送后结算：移除前端报价依赖；后端仅检查账户有效且现金大于零。同账号平台请求串行取得发送资格，结算与消息持久化保持事务和幂等；失败不扣。迁移允许账本与现金负数，部分充值能够抵扣欠款。通过受控上游生成、真实钱包 HTTP、前端发送操作验证正余额跨零、下一条拒绝、失败、重试及并发。
2. 模型价格：分列输入缓存命中、输入缓存未命中、输出，全部使用本站报价与百万 Token 单位。当前上游接口未提供缓存命中价格，标注未提供；有可靠的显式缓存价格时展示，不推算厂商价格。价格页和平台模型选项一致，测试数值与缺失分支。
3. 充值成功引导：管理员配置并保存 QQ 群号，持久化服务器设置。只在充值确认为已入账后提示入群，未设置隐藏。HTTP 验证管理员权限、CSRF、格式、保存和钱包读取；UI 验证配置及到账展示。
4. 学习聊天布局：选择树先显示地图，学习节点时以酒馆占满内容区域，卸载地图渲染，移除聊天拖动分隔条。提供查看地图和返回聊天入口，保留节点、会话及进度。为图快照增加稳定 memo。用户操作测试确认聊天模式没有地图实例；真实浏览器覆盖较大图、桌面及手机切换。
5. 管理员余额监控：服务端调用固定上游 `/v1/skills/balance`，仅管理员可读。管理员面板进入即检查，每 90 秒刷新；耗尽显示横幅，查询失败显示检测异常，不能当作零余额。服务器短缓存合并请求，不向浏览器返回 Key。测试权限、正余额、耗尽、超时与定时刷新。
6. 完整前后端测试、类型检查、构建、Rust fmt/Clippy、自审 diff；合入 main，用生产副本迁移检查后发布至笔记本并完成公网验收。保留运行配置、既有充值与应用回滚容器。

验收沿用用户已确认的前端用户操作、后端 HTTP 及受控模型服务边界；不进行用户真实资金扣款测试。本站不足、上游耗尽与检测失败分别处理。
