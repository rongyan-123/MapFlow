# 酒馆与技能树统一聊天

已由用户确认：技能树右侧使用酒馆，独立酒馆保持布局并改名；角色库、会话、消息共用，不创建第二套聊天数据。

## 行为与边界

- 树入口恢复该树关联的酒馆会话；没有会话时提供以树命名的默认学习助手。已有树聊天历史一次性接入，保留正文，不重复收费。
- 独立酒馆会话可以随时连接自己的个人库条目。会话配置显示目标树与“允许使用技能树工具”开关；角色卡本身不是权限载体。
- 树资料随请求读取。工具授权持久化在会话，关闭后服务端拒绝执行；编辑、切换角色不清空消息。
- 两入口打开同一 conversationId；会话列表和角色库使用相同账号作用域。独立会话无需绑定树。
- 搜索、读取树和经确认的树修改保留。每个工具提案必须匹配当前账号、会话授权及树；删除操作单独确认。
- 平台和自填 Key 都使用受控工具循环。工具多轮请求受轮数、输入和输出预算限制；平台按实际总费用结算，失败释放本站预留，幂等重试不重扣。
- 接入树、切换角色及修改授权使用版本检查，生成期间禁止改变授权；不会让请求中途换到另一棵树。

## 实施步骤与验证

1. 后端 HTTP 连接/授权接口与统一会话绑定：先测试启用、关闭、无权限、版本冲突及消息保留，再实现。
2. 工具与上下文：通过受控模型服务验证模型收到当前树、工具调用需确认、关闭/越权不可执行、工具结果回送及实际费用合计。
3. 前端共用酒馆工作区：用户操作测试覆盖树入口恢复、独立入口续聊、角色切换、工具勾选及目标树选择；随后验证窄面板与手机。
4. 完整前后端测试、类型检查、构建、Rust fmt/Clippy 和 diff 审查；合入 main 后迁移、部署并做公网功能验收。

测试入口为已确认范围中的前端用户操作及后端 HTTP/受控上游模型边界，不通过私有函数或数据库计数代替功能验收。
