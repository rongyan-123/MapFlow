# 酒馆自创角色卡、现金计费与模型渠道数据

日期：2026-10-07。前端基线 main `68eec0d46966d09fd1908bd5c7376fe44d6e8d06`；后端基线 main `32fa7ab3de6019f975337c0faf5a0e89c3120b4c`。状态：用户已确认实施，明确本站按上游本次真实扣费的 2 倍扣现金余额。

用户已确认平台模型正式扣现金额度，每次展示用量、费用和余额；自填 Key 继续由用户自己的上游账户付费。

## 已核实的现状

- 导入角色卡接口支持规范化角色卡以及可选原文件，创建功能可复用现有权限、校验、私有角色库和会话逻辑，不需要第二套角色卡存储。
- 模型价格页面固定写着“额度调用尚未开放”“单价待配置”，渠道代码来自静态列表，36 个灰色方块不连接真实监测接口。
- 酒馆平台模型实现是显式开启的免费试用，现金钱包没有模型消费流水。现有 `creditBalance` 和 `chargedCredits` 对应旧积分，不能当现金余额或现金扣费显示。
- 生产容器没有启用平台试用，也没有挂载 AnyAI Key。笔记本原私有预览目录已有有效 Key，使用该文件只读查询了价格；没有发送付费生成请求。
- 上游 `/v1/skills/models/{model}/pricing` 返回账号实际人民币价格、渠道启用状态、24 小时成功率、平均响应时间及数据来源。九个允许模型均有可用价格组，但部分组没有实时监测结果，须如实展示缺失。
- 旧交接明确约定“上游 0.1 倍率、本站 0.2 倍率”。按该约定，本站收取本次已核实上游实扣人民币的 2 倍，不把上游含代理加价的实付价误当官方原价。
- `D:\mapflow-server-tavern-usage` 有未提交的用量修复：上游尾部仅含费用的 `usage` 对象会覆盖之前的 token 统计。其已有红绿测试与历史实测记录，应审查后纳入本次集成。

## 方案选择

推荐复用现有导入接口创建角色卡，采用现金钱包预留与事务结算，按可信上游本次实扣 ×2 收费。这样自动路由或渠道切换时，最终费用仍对应实际调用，并能准确展示缓存、推理等上游计费结果。

另一种做法是为每个模型固定输入、输出单价，并按 token 计算本站费用。它便于公布固定价，但当前自动路由各渠道价格有差异，需要另立固定价和路由策略，不能直接宣称等于上游实扣 ×2。

仅替换价格文案或在前端减少余额不能完成现金结算，也不能处理并发、失败和重复请求，因此不采用。

## 1. 自创角色卡

在“导入角色卡”旁加入“创建角色卡”按钮。弹窗包含必填角色名称、必填角色设定／提示词，以及可选开场白。保存时构造标准 JSON 角色卡，走现有解析与上传流程；角色设定进入描述字段，遵循现有角色卡编译和站点权限规则。

创建后将新卡加入当前用户私有角色库并选中，用户可像导入卡一样开启会话。保存角色卡本身不调用模型、不扣费。名称最多 200 字符，设定最多 16 KiB UTF-8，开场白最多 8 KiB，并校验完整角色设定符合现有 20 KiB 静态提示词上限，避免创建成功却无法聊天。拒绝空白名称、空白设定和超限内容，保存失败保留表单，连续点击只提交一次。导入 PNG／JSON、官方精选和现有角色卡保持可用。

## 2. 平台模型现金结算

新增明确的正式收费配置，与原试用状态区分。用户选择平台模型时展示收费规则、模型价格及本次可用余额；旧试用页面的请求不能默默转为付费请求，需刷新并确认当前收费契约。

调用前读取带版本的有效渠道价格快照，按本次实际发送上下文和最大输出上限计算保守预留额。价格或模型没有可验证的计费信息时不可进入收费调用。上限必须覆盖允许的自动切换渠道，不能只按最低价预留。余额不足在调用上游前返回明确错误，并显示本次预留额和可用余额。

预留金额、请求归属、会话和 action ID 保存在数据库中，并与当前生成锁／租约绑定。不同会话争用同一钱包时通过数据库行锁或等价条件更新防止超额；前端禁用按钮与进程内信号量不作为资金安全保证。

生成成功后校验完整 token 用量和来自服务器可信上游连接的本次人民币实扣，不接收客户端上报的费用。以整数微元计算本站费用：上游本次实扣 ×2，最终金额按 1 微元向上舍入，零成本保持零。推理 token 不重复计入上游已包含它的输出量。金额格式、币种、负数、非有限数均需校验。预留上限在调用前展示，也是用户本次收费上限；若可信最终费用因上游异常涨价超过该上限，用户扣费封顶，额外成本由本站承担并记录差额，不能透支钱包或事后提高用户已接受的上限。

保存回复、generation 用量、现金消费流水、扣除费用及释放剩余预留在同一数据库事务内完成。重复 action ID 返回已保存的结果、同一账单和余额，不重新调用模型、不重复扣费。旧学习积分账不参与这条现金结算路径；BYOK 不预留、不扣现金。

明确失败或取消时释放未结算预留，未完成回复不产生本站消费流水。中断、进程重启和失去租约的请求必须有恢复规则：不能因为浏览器断开就重新发起相同的上游调用；确认旧生成已终止后释放预留，有可验证完整结果则按原 action ID 完成一次结算。过期释放与成功结算共用同一数据库锁和生成围栏，已释放的旧生成不能迟到后再扣费。缺失用量、缺失费用或异常账单不能按零费用成功提交，也不能猜测归属或金额；返回明确错误并保存失败原因，终止该生成后释放预留，上游可能已经发生的费用由本站承担，不补扣用户。

API 增加明确的现金账单数据，包含计费模式、扣费微元、结算后现金余额、用量和请求标识；保留旧积分字段的含义。每条回复、重新生成和续写均展示对应已保存 generation 的 token 用量与费用，刷新页面后仍可读取。钱包增加“模型消费”流水并更新现金余额缓存，实时结果不得被旧的后台查询覆盖。

## 3. 真实渠道和价格展示

由服务端使用私有平台 Key 读取价格与渠道数据，前端只接收允许公开的字段。Key、上游账户余额和授权头不进入响应、日志或仓库。采用共享短期缓存和并发上限，避免每个用户各自请求全部上游模型；响应提供更新时间、数据来源和是否过期。

模型页展示实际渠道、启用状态、24 小时成功率、平均响应时间，以及本站输入／输出价或价格区间。只有来源标记为 live 的数据标为实时监测；上游估计值与没有实时统计的渠道分别明确标注。接口失败或缓存过期明确提示，不能绘制绿色成功率或伪造历史柱状图。移除目前没有时间序列来源的灰色占位条。自动路由说明与本次最终账单一致，替换已经过时的试用／未开放文字。
