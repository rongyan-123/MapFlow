# 聊天布局与会话删除设计

日期：2026-10-13。状态：用户已确认修订版并授权实施，要求先提交设计、创建开发分支，再自行验收界面和截图，通过后交用户复核。桌面及手机端一起处理。

## 需求与现有实现

用户提供的六张截图指出三个问题：全局助手与学习聊天顶部占用过多，学习聊天叠出五行；会话创建后无法删除；学习聊天「配置」中的五个分类切换时弹窗尺寸变化。

已核对前端 App、LearningChatWorkspace、AgentTavernPage、TavernPage、ConversationPane 和 TavernUi。它们分别输出页面标题、学习区选择、资金模型选择、角色会话操作和画布入口。TavernDialog 设置了最大高度，没有统一配置窗口高度，因此内容决定外框高度。

后端核对目录为 D:/mapflow-server-main-integration-20261006，HEAD 为 a9fb2e3a0a7872d06d4a6df9b8ad6262d5caf927，与当前发布记录一致。现有会话详情路由仅支持 GET，角色卡的 DELETE 接口不能用于删除会话。该目录已有未跟踪的 .ua/，实施时保留其内容。

二次核对确认：TavernPage 的 managementOpening 和 treeStory 会在缺少有效会话时调用默认创建；学习区 treeReady 又依赖当前会话。Agent 的 accept 已在事务中锁定会话，但 resume 首先锁执行记录，public_status/public_events 没有排除已删除会话。旧生成路径还持有 tavern:{account}:{conversation} 的独立生成锁。useTeachingCanvas 有 800 ms 延迟保存及卸载 flush，现有忙闲上报未覆盖这两者。桌面断点为 1024 px。

## 推荐方案与取舍

方案 A：合并为一条聊天工具栏，保留常用操作，将低频操作收进菜单。推荐此方案，直接减少固定占用，同时继续使用现有聊天组件。

方案 B：保留两条工具栏，只压缩间距。改动较少，但仍有重复标题和独立画布行，释放的聊天空间有限。

按方案 A 设计。适用全局助手、具体学习聊天，以及使用相同聊天组件的独立酒馆。学习区列表本身保留列表标题；正在聊天时不再显示独立的「学习聊天」页面标题和重复说明。

## 顶部布局

桌面顶部合并为约 52–56 px 的单行工具栏，包含会话列表入口、角色与会话名称、学习区切换（仅学习聊天）、紧凑资金模型入口、地图入口（仅学习聊天）、画布和配置。角色导入等低频操作放入更多菜单。长名称截断并可查看完整名称；较窄桌面将次要按钮收进菜单，不通过增加整行解决拥挤。

工具栏位于会话侧栏与聊天分栏之上；地图展开后，按实际聊天工具栏的可用宽度折叠入口，不能只判断浏览器宽度。固定保留会话列表、截断的会话标题、新建、画布、配置和更多按钮；窄容器使用图标及可访问名称，并隐藏装饰性头像。

折叠优先级明确为：角色库、导入和说明文字始终在更多菜单；继续拥挤时，依次将资金模型选择、学习区切换及返回列表、查看地图收进更多菜单。菜单中的操作沿用原状态、选择值和权限。标题先缩短，按钮不换行、不重叠，也不制造页面横向滚动。

画布展开、收起和首次创建继续使用现有状态及保存逻辑，入口移入该工具栏。独立画布说明行移除，说明通过按钮提示提供。会话侧栏仍可收起、调整宽度；地图打开后仍可返回原会话。现有手机单行工具栏沿用。

手机端同时检查并整理单行顶部、抽屉的分组与间距、配置分类导航、输入框和回复内容宽度。沿用现有请求与草稿保存方式；覆盖长名称、空态、删除确认、错误与恢复、长代码/表格、横屏和较矮可视窗口。根据真实截图修正拥挤、遮挡和不必要留白，最终交付手机和桌面预览截图，不将浏览器模拟尺寸称为真机验收。

## 删除会话

每条会话历史旁增加独立的删除按钮，避免嵌套在打开会话的按钮内。鼠标悬停或键盘聚焦时显示桌面删除操作；触屏保持可发现的操作入口。点击后弹出确认框，明确会话名称及删除后的结果。

新增 DELETE /api/me/tavern/conversations/{conversation_id}，使用现有登录、账号范围和 CSRF 校验。数据库增加 deleted_at 标记，应用内的历史、详情及后续公共操作均排除已删除会话；保留原始计费及执行记录以维持关联关系。此设计不提供恢复入口。成功及对本账号已删除记录的重复 DELETE 返回 204；不存在或不属于本账号返回 404，不能暴露其他账号的数据。

### 首次进入、主动清空与主动新建

会话列表响应增加 bootstrapState，按账号、场景及学习区范围从数据库计算，不能从浏览器偏好推断。列表只包含未删除会话；历史状态计算包含删除标记，使用同一数据库快照。

| bootstrapState | 服务端含义 | 客户端行为 |
| --- | --- | --- |
| never_created | 该范围内从未有过会话 | 管理助手和可用学习区允许现有的首次默认创建；独立酒馆仍由用户新建 |
| has_active | 存在未删除会话 | 恢复有效的已选会话；本地选择失效时选择同一范围最近一条，不调用默认创建 |
| cleared | 曾有会话，现已全部删除 | 显示可主动新建的空状态；刷新、重新进入和其他设备同样不自动创建 |

默认打开接口也执行此判断。主动清空后，无 newConversation 的管理默认打开及无显式创建输入的学习区默认打开返回 409 / tavern.history_cleared，客户端刷新列表并显示空状态，不展示永久加载状态或继续重试。显式新建仍被允许：管理助手使用 newConversation=true，学习区使用显式创建接口；服务端可从保存的默认角色选择可用角色，必要时按既有规则建立默认角色。

前端将“学习区是否可新建”与“当前会话是否可继续聊天”分开判断。前者依赖学习区可用性、有效角色或服务端默认角色、列表就绪及无创建冲突，不再依赖当前会话存在；地图不可用时仍不能创建。空状态直接提供新建按钮，角色缺失时保留角色选择入口。

删除当前会话后选择同一场景中列表顺序的第一条剩余会话；没有其他会话时置空选择。删除其他会话时保留当前聊天与输入。只有服务端确认删除成功后才更新列表及 bootstrapState、清除详情和本地选择。

删除过程中暂停本范围的自动打开，取消并移除 management/default-conversation、tavern/tree-conversation 两类默认查询缓存，清理匹配的详情、画布和 Agent 公共结果缓存及会话恢复记录；请求结果携带删除前的状态时不得重新应用。随后重新获取列表及其 bootstrapState。服务端默认打开与删除复用本场景已有的 bootstrap 事务锁，防止另一标签页的过期默认请求创建替代会话。删除接口失败时解除暂停并保留原列表、内容和选择。

### 删除、生成与保存的事务保护

删除必须在一个数据库事务内取得账号及会话归属、锁定会话行、检查活动执行并写入 deleted_at，提交前不释放锁。账号串行门禁沿用 agent-account:{account}；默认打开与清空还复用 management/tree 的范围锁。删除不取得执行行锁，避免增加“会话行 → 执行行”的反向锁等待。

Agent accept 在现有账号门禁及会话 FOR UPDATE 下重新检查 deleted_at，检查必须发生在创建执行、关联已有执行和操作重放之前，不能依赖事务外的 authorize_conversation。按执行 ID 的公共 resume/恢复入口先解析所属会话，再通过同一账号门禁锁会话并重新检查删除状态，随后进入执行状态修改；不能先锁执行再新增会话锁。

删除检查 agent_executions 的全部非终态，包括 queued、running、recovering、等待审批和 awaiting_reconciliation；只有 succeeded、stopped、failed 是终态。存在非终态时返回 409 / tavern.conversation_busy，不写删除标记。检查和写标记之间不能提交事务或释放会话锁。

旧生成路径继续使用现有 tavern:{account}:{conversation} 生成锁。删除在取得会话行锁前尝试取得该事务级锁；已有生成持有它时直接返回 busy，不等待生成完成后悄悄删除。旧 begin_turn 发布 runtime_generation_id 时必须在实际写入事务中锁会话并检查 deleted_at，不能只在独立 guard 连接上预读。已有 generation fence、收尾及结算方式保留；旧生成重放也检查未删除状态。

明确并发结果：删除先提交，后到生成、恢复或画布保存必须失败，不新增执行或聊天写入；生成先登记且在删除取得锁时仍是非终态，删除必须返回 busy 并保留会话。生成已经结束后允许删除，以锁内实际状态为准。画布保存和其他会话写入使用同一会话行锁并检查 deleted_at，避免删除后仍写入画布。数据库不能判断浏览器尚未提交的画布草稿，这一部分由下一节的客户端准备流程保护。

### 按执行 ID 的公共访问与内部读取

建立公共执行归属检查，联合执行的 account_id、conversation_id 与未删除会话，而不是在内部通用 execution()/events() 中全局过滤。以下入口必须应用该检查，删除后的新请求统一返回原有安全 404，不携带回复、推理、画布或恢复结果。

公共结果和事件的归属校验与读取使用关联未删除会话的 SQL，或在同一事务快照中完成，不能先单独检查、再调用未过滤的裸读取。事件流每次取页都执行此规则；删除前已经发送的数据不属于可撤回的服务端回放。

| 公共入口 | 删除后的规则 |
| --- | --- |
| GET/POST /api/me/tavern/conversations/{conversation}/executions | 不返回活动执行，不接受新执行、attach 或 clientActionId 重放 |
| GET /api/me/agent-executions/{execution}，public_status | 不返回已保存 result 或执行状态内容 |
| GET /api/me/agent-executions/{execution}/events，public_events | 不回放任意旧游标事件；每页读取都重新验证会话，已建立订阅在发现删除后停止读取并关闭 |
| POST /api/me/agent-executions/{execution}/resume、/stop | 不恢复执行，不通过终态重放返回原回复；修改入口使用上述事务门禁 |
| POST /api/me/agent-executions/{execution}/approvals/{approval} | 不读取或修改被删除会话的审批，不触发工具继续执行 |
| 会话详情、turns、canvas、settings、profile、character、tree-connection、actions、quote、map-generation-draft、旧 tool-approvals | 公共读取与写入均拒绝被删除会话 |

前端清除已删除会话的事件订阅、轮询、恢复存储和进度快照；终止性 404 不进行无限重连。活动执行不能删除的规则不代替这些公共访问检查，已完成执行也不能通过旧 ID 重新取回聊天。

内部 worker、执行日志补录、支付核对、结算恢复和审计保留原始记录读取能力，不依赖公共可见性检查。内部恢复不能让已删除会话重新进入生成队列或追加聊天、画布；已保存的财务记录、结算凭据及幂等结果继续可读。增加“公共访问拒绝、内部结算读取可用”的成对测试。

### 创建请求重放的终止结果

管理与学习区创建先按账号及原范围查 creation_request_id，包括已删除记录；保留现有唯一约束和请求哈希，不能过滤删除记录后尝试 INSERT。命中删除记录返回 410 / tavern.creation_target_deleted，明确表示该创建请求已结束；未删除记录继续执行原有哈希一致性校验和幂等返回。

前端识别该 code 后，清除对应范围且 clientRequestId 相同的 pendingCreation ref 和本地记录，结束 creating/retry 状态，刷新列表，提示“原会话已删除，请重新新建”。不自动发送新请求，也不能清除并发产生的另一条新建请求。用户再次点击新建时生成新的 UUID，不复用旧 ID。普通网络错误和超时仍保留原请求供幂等重试。

### 画布延迟保存、失败与卸载

画布暴露按账号及会话绑定的 queued、saving、failed-with-draft 和 deletion-preparing 状态，800 ms 等待期也算未保存。状态和准备操作保持到在途保存完成，不因聊天组件卸载后上报 busy=false 而提前遗失。普通离开会话仍沿用原有卸载 flush。

确认删除后，先同步进入 deletion-preparing，冻结画布编辑及新的发送/保存入口，停止 debounce 定时器，等待在途保存并 flush 等待中的草稿；全部完成后才发 DELETE。生成、排队、图变更或其他已知持久化请求进行中时，删除操作显示具体忙闲原因并禁止提交 DELETE；画布等待或正在保存时，确认界面显示保存进度，准备流程完成前同样不提交 DELETE。已存在的非当前会话保存任务也按该会话 ID 查询，不使用当前会话的单一 generationBusy 代替。

画布 flush 失败则不发 DELETE：保留元素、失败状态和会话选择，解除冻结，提供“重试保存”与“取消删除”。只有保存成功后才能继续删除；本次不新增隐式丢弃草稿的路径。删除接口失败同样解除冻结，并保留已成功保存的画布。

删除成功时，在卸载旧组件之前将对应画布生命周期置为 deleted、清除定时器、队列及订阅，cleanup 不得 flush；晚到回调根据会话 ID 和生命周期忽略，不能更新新会话或再次入队。另一标签页晚到的 PATCH 由后端会话行锁及删除检查拒绝，不重新创建画布。

## 配置弹窗

带分类的配置窗口统一外框：桌面最大宽度约 1024 px，高度为 min(720 px, 视口高度 - 48 px)。五个分类使用相同标题栏、左侧导航宽度及内容区。切换分类不改变外框位置或宽高；短内容保留留白，长内容在右侧区域滚动。

小屏按可用视口限制尺寸，沿用手机分类导航、焦点约束和关闭后的焦点恢复。无分类的导入、删除确认等普通弹窗保留按内容适配的尺寸。

| 5. 画布生命周期 | 假时钟覆盖 800 ms 等待期，在途保存结束前不发 DELETE；保存失败不删除且可重试；取消/DELETE 失败保留画布；删除后卸载、推进定时器及晚到回调均不发旧 PATCH；另一标签页 PATCH 与删除交错不写删除后的画布 |
| 6. 工具栏拥挤 | 1024 px、侧栏最大宽度、地图展开且聊天最窄、长名称的各项及允许的组合仍单行且无溢出；折叠入口能执行原操作且保留选择；1023/1025 px 断点两侧同样验证 |

## 验收标准

- 正常桌面聊天顶部由多行合为一行，消息区获得释放的高度；输入草稿、模型选择和画布保存正常。
- 删除入口可发现、可键盘操作；取消不发删除请求，成功后历史刷新不恢复已删会话，失败不丢内容。
- 当前、非当前、最后一条会话删除后的界面均可继续使用；活动执行受到保护，账号权限测试通过。
- 主动清空在刷新和其他设备上保持空态，用户仍可新建；缓存和晚到默认响应不能恢复旧会话。
- 删除先提交时拒绝后到生成；生成在删除锁内检查时仍活动则拒绝删除，不能发生已删除会话继续接收执行；公共执行 ID 不能取回已删除内容，内部财务记录可继续读取。
- 旧创建请求得到终止性结果，新建使用新 ID；画布未保存时不能提交删除，成功删除后卸载不再提交旧画布。
- 1024 px 及可用聊天宽度最小的组合仍满足单行和无横向溢出，收进菜单的功能可继续操作。
- 配置五个分类的弹窗外框一致，长内容内部滚动，小屏操作可用。
- 全部必需测试和检查完成并记录实际结果。
