# MapFlow 产品页滚动叙事与 3D 场景升级设计

## 目标

在不牺牲真实 3D 视觉效果的前提下，升级 MapFlow 产品介绍页的滚动体验和技能树舞台：

- 保留 React + Vite + Three.js + React Three Fiber 的真实 WebGL 3D 场景；
- 让产品页的主叙事由 SVG 曲线和连续滚动进度驱动，而不是普通 section 逐段切换；
- 让技能节点更像有厚度、有材质的空间实体，铭牌附着在节点上并随节点旋转；
- 增强空间氛围，但不引入服务器端渲染、每帧后端请求、大型外部模型或 Gaussian Splat 资产；
- 保持无 WebGL 降级、键盘可理解性和移动端可用性。

本轮只改产品介绍页，不改控制台、后端、数据库、计费、登录协议或部署配置。

## 资源与运行边界

Three.js/R3F 只在访问者浏览器中运行。服务器只提供页面静态资源，产品页 3D 场景不得在动画帧内发起网络请求。

本轮使用当前脱敏演示节点和程序化几何，不直接搬入 JL 项目中的大型 GLB。背景氛围使用轻量的点状粒子、雾和灯光层；JL 的 FBO 粒子形变与 Gaussian Splat 保留为未来可替换方向，不作为本轮硬依赖。

## 交互设计

### SVG 滚动叙事

新增独立的滚动叙事区域，内部包含一个 sticky 舞台和一条 SVG 路径：

- 原生滚动容器的滚动位置换算为 0 到 1 的故事进度；
- SVG 路径以 `pathLength="1"` 配合 `strokeDashoffset` 连续绘制；
- 四个学习章节根据局部进度平滑进入、停留和离开；
- 章节卡片的透明度、位移和缩放由纯函数计算，方便单元测试；
- 滚动容器进入或离开视口时不创建额外网络请求；
- `prefers-reduced-motion` 下保留内容和路径，但减少位移与过渡。

不引入 Lenis 或 GSAP 作为本轮必要依赖，先用原生滚动和 `requestAnimationFrame` 控制，避免与现有自定义滚动容器产生冲突。

### 3D 技能树

保留当前 OrbitControls 的鼠标/触摸旋转、平移和缩放能力，并做以下升级：

- 节点主体由简单的 icosahedron 改成有倒角和厚度的圆角实体；
- 使用边缘线、内层核心和选中光环增强材质层次；
- 标签容器使用 Three.js 3D 变换附着到节点，不使用 billboard 作为唯一呈现；
- 保留 DOM 文本摘要和无 WebGL 2D 降级，保证内容可访问；
- 使用 `useMemo` 复用静态几何和材质，限制像素比；
- 粒子保持为轻量的程序化 Sparkles，不接入大型模型或服务器数据。

## 组件边界

- `LandingPage`：保留产品页结构，挂载滚动叙事组件；
- `LandingStory`：只负责故事进度、SVG 路径和章节 DOM；
- `landingMotion`：提供可测试的进度、章节和路径计算函数；
- `SkillTree3D`：只负责演示 3D 舞台和节点交互，不读取真实用户数据；
- `SkillTree3D` 内部实体节点：只消费演示节点数据和选择回调。

## 测试与验收

### 自动测试

1. 先增加 `landingMotion` 的失败测试，覆盖进度钳制、章节局部进度、路径绘制进度和 reduced-motion 状态；
2. 增加 Landing 页对滚动叙事容器、SVG 路径和四个章节的公开结构测试；
3. 实现最小逻辑后跑红转绿，再重构重复样式；
4. 运行全量 Vitest、typecheck 和 production build。

### Browser Harness

- 桌面端打开产品页，实际滚动，确认 SVG 路径和章节状态连续变化；
- 实际拖拽 3D 舞台，确认视角仍可旋转；
- 点击节点，确认节点摘要仍然切换；
- 点击重置视角，确认 OrbitControls 仍然可用；
- 在窄视口和手机视口检查无横向溢出；
- 检查页面切换到控制台的 CTA；
- 检查页面加载时没有因动画产生额外 API 请求。
