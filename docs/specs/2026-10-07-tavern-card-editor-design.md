# 酒馆角色卡编辑

用户已确认：左侧卡片悬停显示操作菜单，支持重命名、编辑、删除；编辑同步到当前会话下一轮，已有消息和其他旧会话保留；删除保留历史。桌面、触屏、键盘均能操作。

## 交互

卡片主体继续负责选择/继续故事，独立的 `⋯` 按钮打开操作菜单，操作不触发选择或新建会话。编辑窗口预填角色库当前版本，基础字段为名称、角色设定、性格、场景、开场白，高级字段为示例对话、系统提示、历史后指令、作者备注。世界书、备选开场白、头像及原始文件保持原值。重命名只修改名称，取消不发送更新。

保存更新角色库；若该角色有当前选中的会话，同时在一个事务中更新该会话角色快照、提示词及配置指纹，从下一轮生效。既有开场消息、对话消息、分支、消费记录和其他旧会话不改写。新开场白用于新会话。移除角色采用现有软删除，确认后移出角色库但保留聊天。

## 接口和一致性

`PATCH /api/me/tavern/characters/{id}` 接收 `expectedHash`、完整规范化 `card`、可选 `conversation: { conversationId, expectedRevision }`，返回 `{ character, conversation }`，其中 `conversation` 为已更新会话详情或 null。后端要求登录、CSRF 和账号归属，复用角色卡内容校验，限制请求大小。角色哈希和会话 revision 防止覆盖其他标签页的新修改；更新当前会话复用生成互斥锁，生成中返回 409，事务整体不修改。

原始导入文件及其哈希保持，下载按钮仍标注为原始角色卡。不新增数据库迁移。保存成功取消旧查询并同步角色、会话和详情缓存；冲突保留草稿，提示重新打开编辑窗口读取最新版本。

## 测试与发布

按已确认的两个边界测试：前端用户操作和后端 HTTP 接口。先验证红灯，再实现绿灯，覆盖编辑/取消/重命名/删除、保留历史、下一轮与新会话设定、其他会话隔离、过期版本/生成互斥、跨账号/CSRF、输入校验和原始文件保留。运行完整前后端测试、类型检查、构建、fmt/Clippy及 diff 自审，桌面和移动端检查，合入 main 后部署笔记本。发布前克隆生产数据库验证，保持钱包和运行配置，仅保留应用回退。
